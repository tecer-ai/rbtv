# planning

The planning-door lock, Path A mint, Path B birth, and supervised-materialize wrapper. Not a CLI — mint/birth import these modules.

| Part | One line |
|---|---|
| `lock.py` `take_lock` | Exclusive flock on `<goal>/planning/current/.materialize.lock`; same pass-id re-enters; distinct trigger refuses `lock-collision`; dead pid is stolen |
| `wrapper.py` `supervised_materialize` | Shared path-A/path-B wrapper: validate → uncast → scaffold (B) → lock → mint → release; five failure classes; no Slack |
| `wrapper.py` `uncast_in_sheet` | Refuse-before-write: any seat without harness+model refuses the whole act |
| `argv.py` `planning_mint_argv` | The mint argv both paths build: `--package` at the goal; never `--milestone-id`, never `--nested`, never full/collapsed. `goal_local=True` takes the `--goal-local` lane and FORCES `--workflow goal-local` (the lane synthesizes exactly one manifest); `creation_inputs=` names the two caller-supplied base texts a BRAND-NEW package needs (`--claude-md`/`--budget-json`), which Path A never passes and Path B always does |
| `path_a.py` `run_path_a` | Path A caller: uncast + wrapper + one materialize invocation |
| `path_b.py` `run_path_b` | Path B birth: validate-then-scaffold-then-mint; reclaim folder+catalogue on mint fail. Scaffolds with `--materialize-follows` (this act DOES mint, and a daemon-lane scaffold without it is refused); stages the plan artifacts AT THE BOUND COMMIT and reads the contract from there; a package with no `workflow` is a ONE-OFF PLAN — its `planning/current/` is copied into the born goal and minted `--goal-local`; `catalog_root` defaults to the rbtv `meta` tree through `rbtv.json`; a goal minted without its chairs refuses `birth-chairless` and is reclaimed |
| `path_b.py` `main --package` | The daemon's entry into Path B: `state-store/heart/start-execution.js` writes the approve-package and runs this on the fourteenth gateway intent `start-execution` (owner ruling 2026-08-24 (b)) |
| `door.js` `pipelineMinted` | The pipeline-seat MIRROR, and the one executable statement of "minted": every name in `pipeline-seats.json` is a `seat` row on the goal's `taskforce.csv`. The per-tick mint pass this file used to carry was DELETED 2026-08-28 — its admission key, a `goal.md` frontmatter `role: planning`, had no producer in any creation route (`goal_cli.py#cmd_scaffold` writes six keys and no `role`), so it fired 0 times in 592,458 journal lines. The five seats are minted AT BIRTH by the creation route instead |
| `pipeline-seats.json` | Mirror of the `plan-console` manifest's `Seat/workflow` column — the seat ids `argv.py` uncasts and mints from; divergence silently mints a set the manifest cannot produce, and `queue-request.js#planningManifestSeats` + probe leg M are the alarm |
| `materialize-seats.py` derived-tree refusal | The lane builder plants `DERIVED.md` at the `seat-lane/` root (`source: ..` = `planning/current/`, plus its regenerator); `_ref_target` and the five non-lane writers call coord's `refuse_if_derived`, so an `exposes` target or a seat surface resolving UNDER a marked derived root refuses `target-under-derived-tree` (C10). The lane REGENERATOR is exempt by construction — it stages and replaces the root rather than writing through a guarded door. spec-component-map §4 |
| `approve_package.py` `write_approve_package` | The WRITER of `<planning goal>/planning/approve-package.json` — what the fourteenth gateway intent reads on `approve` to learn WHAT to build. Validates the execution-goal name against BOTH its readers (`bus-ferry.js#isSafeName` and `goal_cli.py#GOAL_NAME_RE`, the narrower lowercase-kebab rule the scaffold enforces) and the bound commit against the reader's own rule, REFUSES the three daemon-stamped keys (`planning_goal`, `goals_root`, `origin_id`), refuses a `--contract-file` that is not a file under `--plan-artifacts` (`bad-contract-file`) and, on a package with no `--workflow`, any disagreement between the roster and the plan's own `current/manifest.csv` in EITHER direction (`roster-not-in-plan`) — the manifest is what `--goal-local` mints, writes through coord's `atomic_write` (tmp+rename + the derived-tree refusal). Run by the planning pipeline's verify seat |
| `failure.py` | Record fields `origin`/`origin-id`/`class`/`code`/`subject`/`reason`; D12 approval-thread; D13 gate-lane `incomplete: materialize-failed`. `class_for_code` derives the class from the refusal CODE — `roster-name-collision` only for a name already held, `atomic-core-refusal` for every other gate refusal |
