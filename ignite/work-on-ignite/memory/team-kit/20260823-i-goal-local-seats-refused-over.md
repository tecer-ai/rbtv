## Observed
Two live goals were frozen at seeding and could not build a single goal-authored seat. `meet-transcript-summarizer` was frozen from 2026-08-23 02:34Z for roughly 13 hours: all four of its m3 build seats (`source-adapter-smith`, `meeting-matcher-smith`, `cycle-spine-smith`, `detection-suite-author`) plus `plan-7-plan-planner`, which was already BUILT, READY, on a different milestone and depended on none of them. `stools-canvas-audio-elevenlabs` was frozen from 13:40Z: `audio-gap-prober`, its only READY seat and the root of the m2 gap-fill wave. The daemon retried every ~10s and refused every time — 688 `goal-local-lint-failed` occurrences in 24h on stools alone. Reproduced first-hand from a console: `materialize-seats.py --workflow goal-local --goal-local --milestone-id m3 --force-partial --dry-run` against the live meet goal returned `exposes-ref-dangling`, path `<goal>/planning/current/seat-lane/goal-local/goal-local`, message "is not a depth-2 component in scan_all". team-kit Python is live-tree, so HEAD and the deployed tree are the same file here.

## Mechanism
In `_ref_target`, the line `own = _own_component_id(comp_dir, catalog, mirror, repo)` was evaluated UNCONDITIONALLY, one line before the branch that decides whether `own` is needed. `_own_component_id` identifies the referencing component by matching it in `scan_all` or by `resolved.relative_to(root)` against exactly two roots — the mirror and the rbtv repo — and raises `Refuse("exposes-ref-dangling")` when neither matches. The goal-local lane that `build_goal_local_lane` synthesizes at `<goal>/planning/current/seat-lane/` is a THIRD tree under neither root, by construction. The reference grammar the function enforces is `part`, `component/part`, or `module/component/part`; only the first two forms are DEFINED in terms of the referencing component's own identity. A three-segment reference is fully qualified and never reads `own` — so every goal-authored seat was refused over an identity its own reference does not use.

## Attempts
The regression was introduced by `0563266b` (2026-08-22 14:56, the D86 discovery work), which replaced this function's pure path arithmetic — `comp_dir.parent.parent / segs[0] / segs[1]`, root-agnostic and satisfied by the symlinks `build_goal_local_lane` deliberately creates — with a catalog lookup plus this identity step. Confirmed with `git log -S`: both `_own_component_id` and its `for root in (mirror, repo)` loop first appear in that commit. THREE separate register filings diagnosed this defect and ALL THREE were wrong, which is why it survived: `G-goal-master-0823-1207` asked for the "doubled `goal-local` segment" to be removed — but `GOAL_LOCAL_MODULE` and `GOAL_LOCAL_COMPONENT` are both deliberately `"goal-local"` and the comment beneath them reads "THE MODULE LEVEL IS LOAD-BEARING, not decoration", added 2026-08-15 to fix an earlier instance of this same refusal; implementing that filing would have re-broken what that fix repaired. `G-leader-0823-0217` and `G-goal-master-0823-0209` both named the surface as `ignite/engine/seeding.js`, where a fixer would find nothing. Reverting `0563266b` was also checked and rejected: `core/communication/audio`, the tool stools is building, exists ONLY in the mirror while the lane's symlinks point at the rbtv repo, so only the post-D86 catalog spans both trees.

## Fix
`own` is now resolved INSIDE the two branches that read it, so a three-segment reference never triggers the identity lookup. The narrow fix was chosen over the alternative — teaching `_own_component_id` that the generated lane is a legitimate third tree — precisely because the broad fix would ALSO have re-enabled one- and two-segment references from goal-authored seats, silently overturning the stools leader's ruling `p-goal-local-seats-cannot-use-bare-part-ids-2026-08-23`. Under this fix those short forms still refuse from the lane, which is the correct and ruled behaviour. A comment at the site states the laziness is load-bearing and must not be hoisted back.

## Consequences
Nothing was deleted; the one- and two-segment paths are unchanged. stools is NOT fully unblocked by this alone: `audio-gap-prober` declares a ONE-segment reference (`stools`), which can never resolve from a goal-authored seat because the lane carries no `exposure.csv` of its own, so it still needs a content edit to a three-segment form. Measured after this fix: `meta/planning/stools` — the form proposed in stools' unanswered owner escalation #282 — now RESOLVES. It had been measured as failing before this fix, when the eager lookup refused everything first, which made the escalation read as proposing a fix that did not work. It does work, but only downstream of this change. Filed as build-ignite task 128.

## ATTENTION
- The three register filings on this defect ALL state the cause wrong. Do not implement `G-goal-master-0823-1207`'s "remove the doubled goal-local segment" — that doubling is deliberate and load-bearing, and removing it re-breaks the 2026-08-15 fix. Do not send a fixer to `ignite/engine/seeding.js`, which the other two name; the code is in team-kit.
- Do not hoist `own` back out of the branches "to avoid computing it twice". It is resolved lazily so a fully-qualified reference is never refused over an identity it does not use. Hoisting it re-freezes every goal that authors its own seats.
- The one- and two-segment forms still refusing from the lane is CORRECT, not a residual bug. It is the ruling `p-goal-local-seats-cannot-use-bare-part-ids-2026-08-23`. A "fix" that makes them resolve overturns an owner-adjacent ruling silently.
- `build_goal_local_lane`'s sibling-symlink loop exists so `_ref_target` could resolve `module/component/part` through path arithmetic. Post-`0563266b` the resolver returns real catalog paths and may never walk those symlinks — but that loop already caused one production incident (`20260822-i-lane-symlink-scope`, `.git` symlinked into the lane), so measure before deleting it, and treat it as a separate change.
