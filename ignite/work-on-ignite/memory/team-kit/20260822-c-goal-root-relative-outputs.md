## Motivation
On the live `meet-transcript-summarizer` goal, `cmd_checkout` in `coord.py` grades a finished seat by requiring an `## Outputs` backticked path that `_IOSPEC_PATHISH` accepts (`/` + extension). Shared planning templates that write at the goal root — `goal.md`, `milestones.csv` — had no subdirectory to name, so their `Write:` text was a bare filename. The regex never matched; the gate stamped the row `unverified`; the next seat stayed unrunnable. D55 (2026-08-22) named the root: every shared planning template must project a real path, or the gate's accepted shape must reach its producer. D73 then restricted the first fix to templates only — "No gate widening" — and seat `03-outputs-594` put `` `./goal.md` `` / `` `./milestones.csv` `` on `review-goal-completeness.md` and `structure-milestone-dag.md`. That spelling already matched PATHISH (the regex was never the blocker). It did not hold: `declared_outputs()` still excluded any `./`-prefixed token from the goal-root candidate list, so the files sitting at the goal root were checked only against the empty seat cwd. `redesign-plan/status.md` recorded both outputs remaining `outputs-undeclarable` and D55 only half-closed. D90 (owner, 2026-08-22) is option A of #594's second half: extend the grammar so a goal-root-relative output is declarable and those two templates stop being leader-flipped.

## How it works
`_goal_root_dotslash(d)` in `declared_outputs` (`coord.py`) is true only when the token starts with `./` and the remainder has no further `/`. The candidate-list condition became: if a goal dir is known and the token is not absolute, insert `Path(_goal) / _d` first when the token is either not `./`/`../`-prefixed (the older D36 bare-relative widening) or is this single-segment `./name.ext`. The cwd candidate from `resolved_outputs()` is still tried, unchanged. Template authors declare a goal-root file as `` `./name.ext` `` in the `Write:` clause (and therefore in `## Outputs`); `review-goal-completeness.md` writes `` `./goal.md` ``, `structure-milestone-dag.md` writes `` `./milestones.csv` ``. A deeper `./sub/deep.md` stays cwd-only. Seeding a READY predecessor still uses `resolved_outputs` only — a `./name.ext` seed path remains seat-private even after D90.
