## Design

Owner rejected D24 option (c) — stuffing `goal-master` into `STAFF_SEATS` — because that tuple is read at four unrelated sites (`is_staff_seat`, the staff-mail arm, launch admission, `--route` choices) and would change mail, admission, and routing to buy one exclusion. First attempt held — checked: `git log --before=2026-08-19 --grep=goal-master` on `coord.py` and `materialize-seats.py` returned only unrelated prior work (P1 pane supersession, AGENTS.md descriptor, ready-seats relaunch grants).

`aa1920a8` opened the mint door: a summoned seat joins a multi-taskforce goal's first bare id the same way a staff chair already did (`d-staff-chair-joins-first-taskforce`, 2026-08-14). `--seat goal-master` had refused `taskforce-id-unreadable` because the chair is neither staff nor a workflow node and the live goals carry many bare ids. The lift is keyed on the added set being first-taskforce joiners (staff ∪ summoned); `STAFF_SEATS` stays untouched and ordinary seats still refuse the guess.

`61ce15d9` taught reconcile the same exclusion. Failed read / older coord yields the empty set (pre-fix behaviour + warn, never a silent hole). Staff chairs stay owed; a leader relaunch on unread mail is the watcher's purpose.

`eda7e4c7` implemented D29: `cmd_checkout` accepts a summoned chair's `done` with a zero-token `## Outputs` block instead of downgrading to `incomplete` (`outputs-unverified`). Same commit also closed the kit-side D24 hole in `close_staff_mail_arm` and stripped a docstring that claimed a staff chair never checks out.

## How it works
Mint `goal-master` with `materialize-seats --seat goal-master`. `materialize-seats._first_taskforce_joiners()` imports `STAFF_SEATS` and `SUMMONED_SEATS` from `coord.py` (F6: never re-list the names) and, when the added set is a subset of that union and the goal already has more than one bare id, assigns the earliest existing bare id. After mint, `ready-seats` reports the chair IDLE with reason "ON-DEMAND summoned seat … NOT OFFERED"; an ordinary root on the same taskforce still reads READY. Mail is not a wake term for a summoned seat (staff chairs still wake on unread mail). Conjunction admission is untouched — `launch --only goal-master` still admits. The actual summon is a bot-tag / forward-path enqueue that does not read this verdict (D11 piggybacks here; it has no standalone commit).

Reconcile's `summonedSeats()` execs `coord.py` and parses `SUMMONED_SEATS`; `deriveOwed` skips those names in both owed classes. A new trigger (owner summon) still wakes the chair; after `done` it must not auto-relaunch — D30's binding polarity pair.

At checkout, `cmd_checkout` consults `is_conversational_chair(me)` (today `goal-master`, `leader`, `consultant`). A conversational chair's `done` stands with zero path tokens; a `prose` control on the same zero-token `## Outputs` is still refused. `close_staff_mail_arm` reads `is_summoned_seat` directly: a summoned chair's kit close mints no leader note and no staff wake; the row still lands `exited`/`kit`. An ordinary seat (`alpha`) on the same closer still mints both.
