## Motivation

D42 (2026-08-20) built `launch --only <seat> --rerun <leader-anchor>` so a leader could re-run a kit-written `exited` row — six revival paths had all been measured shut. The chair that holds the verb could not fire it. `asserted_launch_claim` (F17, wired at `launch` alone) corroborated `--as` only through `detect_pane()` + `pane_agent()`: a real `%NNN` tmux pane against an active roster row. A caged leader has no `TMUX_PANE`. Meet-transcript-summarizer's leader, checked in at 19:45Z holding roster row `sid:c22b6807-…`, was refused: "this process is not inside any tmux pane, so there is no roster row to check it against at all". `--force` does not lift it — D43: "an identity that could be forced would be an assertion again by another spelling". That is the door this creation opened: a paneless caller must prove who it is without reopening impersonation hole G-111.

The same evening and the next day the door needed three more rulings. D43 shipped and a second gate still refused the same command. Both D43 and D45 then shipped "verified" and were still refused in production (F-6). After F-6 made the cgroup readable, `resolve-verify` PASS 4 (2026-08-21) measured a caged seat acting `--as` any staff chair on every command except `launch` (F-8).

## Design

Four commits, four holes, one shared corroboration. D43 (`23de241f`, 2026-08-20 20:28Z) adds `carrier_self_session()`: read `/proc/self/cgroup`, recover the `rbtv-worker-<sessionId>` unit minted by `spawn/carrier.js`, key the roster on `sid:<id>` exactly as `pane_agent` keys on a pane. Comparison to `claim` is deliberately asymmetric with the pane branch — `resolve_agent`'s contradiction check reads `''` for a paneless caller and would fire on nothing. Rejected: "accept a live `sid:` roster row as it accepts a pane" (a bare name match proves nothing about who is calling; reopens G-111). Same commit bundled D44 (`stuck` becomes a brake on `engine/reconcile.js`) — orthogonal, filed as `engine/20260820-c-stuck-becomes-a-brake`.

D45 (`70eb50de`, 2026-08-20 21:16Z): D43 is necessary but not sufficient. `_staff_claim_gate` (W3/D-2) still refused a caged leader because it resolves to `ignite-daemon` (no pane; the daemon injects no `COORD_AGENT` for headless seats — it appears nowhere in `server/spawn/**` except probes proving it is ignored). The gate exists to refuse an asserted identity; once the caller has proven the claim against a kernel-observable fact, it is no longer an assertion. `carrier_corroborated_seat(args)` is factored out of `asserted_launch_claim` so both gates share one call and cannot drift. Rejected: dropping `--as` (the run record would name the daemon as the actor that re-ran the seat — the who-wrote-this distinction D32/D33/D39 spent the day making trustworthy); injecting `COORD_AGENT` at headless spawn (identity on an env var any local process can set — the same objection that killed the leader's original D43 proposal). `--force` still does not lift it.

D46 / F-6 (`2138307d`, 2026-08-21 03:11Z): both D43 and D45 shipped "verified" and were still refused in production. Two independent defects, and closing either alone left the door shut. First, `bwrap.js` passed `--unshare-cgroup` inherited from decomposing `--unshare-all` in `ac4726a6` — never a chosen identity protection, no cgroupfs mounted in the cage — so in-cage `/proc/self/cgroup` read `0::/` and `carrier_self_session()` failed closed everywhere it was meant to run. D43's own new refusal ("…and its own cgroup names no daemon-minted session either") is itself that third state. Second, not "two different id strings" as the F-6 handoff first claimed: `carrier.js` names the unit after `session-id` (heart.db invariant `unit_name == 'rbtv-worker-' || session_id`, 100% of rows); `native-session-id` is the harness transcript id whose only consumer is `claude --resume`. The real defect was paneless check-in taking its roster token from `sessions_open_ids(...).get(agent)` — last OPEN row in file order — not the row tied to the caller's own carrier unit. Two causes made that the wrong row: stale never-closed open rows (`session_close` only closes the LAST open row; 8 measured on meet, including a leader row from 2026-08-18) and an append-after-launch race (`spawn.js` runs the harness before appending the session row). Of the handoff's "10 differing rows", only 2 were D43 breakers (the two leader rows). Owner ruled option (a): drop `--unshare-cgroup`; register `sid:` from `carrier_self_session()` first, last-open-row fallback only for carrier-less callers; `lifecycle_recipient_live` moves from equality against last-open to membership among the seat's open rows (the live leader had read as an empty chair for a whole sitting). Rejected option (b): a daemon-side arbiter over a new tokenless endpoint ("largest new attack surface: a tokenless daemon endpoint reachable from every cage"). Also rejected as identity: an environment variable (forgeable), an in-cage PID proof (collapses into needing the daemon arbiter anyway), systemd credentials / `sd_notify` (`/run` is tmpfs-masked; `NOTIFY_SOCKET` is an env var). Deviations from the synthesis, disclosed in D46: P2 (append the session row before launch) deliberately not done — the row carries `pid`/`pid-starttime` another gate matches against live `/proc`; P1 (close the stale open rows) closed 0 — `--go` blocked by the session's permission classifier.

F-8 (`70328baa`, 2026-08-21 16:24Z), found the next day by `resolve-verify` PASS 4: a caged seat could act `--as` any staff chair on every command except `launch`. `_staff_claim_gate` ran D45 corroboration only when `actual` was already non-empty; inside a cage `actual` is routinely `''` (no `COORD_AGENT`, no `heart.db` bound, `/run` is tmpfs so `systemctl --user` cannot answer), so the guard was skipped and the cage fell through to "nothing resolves = uncaged console". Pre-existing, not a D46 regression — D46 made the cgroup readable so the hole became measurable. Fix: corroboration runs before `if actual` and fills `actual` from the proven roster seat; an uncorroborated cage hits a dedicated refusal instead of the console admission. The gate's own comment had asserted the opposite ("a CAGED seat always carries `COORD_AGENT`") and was corrected in the same change.

`b6c64a25` (D49, 16:49Z) is a same-day companion consumer, not part of the identity-gate mechanism: `secret-add` refuses workers and bare `--as master` via "the F-8 identity ladder". Filed under `server/20260821-c-secret-add-mediated`.

## How it works

A caged leader that wants to `--rerun` a crashed row fires the same command it always would: `launch --only <seat> --rerun <anchor> --as leader`. Two gates stand at that door, both now reading `carrier_corroborated_seat(args)`.

`carrier_self_session()` opens `/proc/self/cgroup`, runs `daemon_worker_unit`, requires prefix `rbtv-worker-` (`CARRIER_UNIT_PREFIX`), returns the session id or `''`. Nothing in argv or the environment reaches it; the `cgroup_text` parameter is the self-test seam only. Fails closed on unreadable or unmatched input.

`carrier_corroborated_seat` returns `(sid, pane_agent(base, "sid:"+sid))` — which seat the roster registers against that session — or `('', '')` when this process is not inside a daemon-minted unit. `register=False` is load-bearing: a guard that claims it refused and acted on nothing must not have written a registry entry first.

`asserted_launch_claim` (F17, `launch` only): pane match first; if no pane, admit when `seat == claim`. Asymmetric with the pane branch because `resolve_agent`'s contradiction check is pane-keyed and would fire on nothing for a paneless caller. Refusal text names all three ways out (check in, run from the registered pane, `--dry-run`).

`_staff_claim_gate` (inside `resolve_agent`, every command): resolve `actual` from pane / `COORD_AGENT` / `daemon_exec_identity()`; then call `carrier_corroborated_seat` and fill empty `actual` from the proven seat (F-8). If `actual` is not in `STAFF_CLAIM_IDENTITIES`, admit only when `_seat == claimed`. An uncorroborated in-cage caller (`_sid` set, `actual` still empty) hits the dedicated F-8 refusal, not the console admission. `--force` is never consulted. The refusal now also reports what the caller's own session is registered to.

Paneless check-in registers the roster `sid:` token from `carrier_self_session()` first, falling back to `sessions_open_ids` only for carrier-less callers. `lifecycle_recipient_live` treats the roster token as a member of the seat's open rows, not as equal to the last-open row — the two can diverge during a boot window.

`bwrap.js` `buildBwrapArgv` unshares user/ipc/uts only — not pid (D3/D8) and not cgroup (D46). `--tmpfs /run` stays: the user systemd bus remains unreachable. JS is inert until `rbtv ignite daemon deploy`; `coord.py` is live on commit.

Measured false for 10 of 403 rows, all in the paneless lane; of those only 2 were D43 breakers. `2138307d` corrected the docstring in place — a silent revert re-derives the handoff's wrong defect-2 ("two different id strings") that D46 recorded so it would never be re-derived.

A regression in `carrier_corroborated_seat` or `_staff_claim_gate` lands silently; run the file by hand after touching identity-gate code. The in-process `coord.py selftest` cannot cover this subject — the logic under test is what the running process's own cgroup names.
