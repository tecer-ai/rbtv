## Motivation
Once a seat ended `done`, the leader had `--rerun` (D42) for kit-written `exited` and `--declare-only` for an undeclared ending, and no door for a late finding against finished work. Rewriting the closed row would break the append-only history D54 later named as the invariant, and would hide that successors had already run on that `done`. Owner, 2026-08-22 ~00:30–01:30Z system-problems interview (`redesign-plan/decisions.md` D54): a leader-written `done` may be re-opened on a late finding by appending a new sitting with a recorded reason; the `done` row stands unrewritten. Design direction endorsed in the same ruling: fewer, stronger invariants — append-only history, one brake, fewer row states. Round 2 the same day (~11:10–11:40Z) bound the capability: D66, the D52 brake budget is per (goal + seat + reason), a D54 re-open counts against it, and the brake ships before re-open so the door is never unbounded; D72, the reason is a new column on the NEW sessions row and the system flags downstream seats that already ran on the retracted work (graph walk-forward — owner chose the fuller option, effort L). D76 still listed #635's class fix D54 as unbuilt at interview close; `17d75459` is that build.

## How it works
`$COORD launch --only <seat> --reopen "<reason>"` (help line added to `protocol.md` in the same commit). Empty reason is refused at the input layer (exit 2) — "an empty one would re-open finished work citing nothing." Admission then: `--only` must name exactly one seat; `sessions_last_ended_rows` (the same selector `--rerun` uses) must show that seat last ended `done` by an admitted `done` writer; any other disposition is refused by state, with a routing table pointing `exited` → `--rerun`, `incomplete` → the watcher, `unverified` → `rule-disposition`, empty → `--declare-only`. `reopen_attempt_count` refuses a third sitting under the identical (seat, reason) pair (budget 2); a genuinely new finding needs its own reason string. P4 refuses if a live pane already holds the name. `reopen_downstream_seats` walks `taskforce.csv` `after` via `_reopen_predecessor_names` (both limbs of an `a|b` alternate, because reopening either retracts a `done` the alternate may have been satisfied by) and keeps only seats that already have a sessions row; it is computed at admission so `--dry-run` still prints the D72 banner, and it never rolls back, re-blocks, or touches another seat's row.

After a real launch the reason is written only if `sessions_open_ids(pkg).get(seat)` returns a new session-id: locate that row by session-id (never by the seat's last row), set `reopen-reason`, and if downstream existed append a kit→leader `messages.md` note then suffix the cell ` (downstream flagged in messages.md #N)`. The write is gated on that open id, separately from `_reopen_admitted`, because the capacity gate can defer an admitted seat after admission and before `launch_seat`; writing the last row in that case would mutate the `done` row D54 forbids touching. Downstream relaunches of the new sitting's own non-`done` ending still hit brief 07's queue-side brake; this door does not exempt them.

## ATTENTION
- The `reopen-reason` cell is written only on the freshly-opened row, located by `sessions_open_ids` then matched by session-id — never via `sessions_last_ended_rows` or "last row for the seat". The write is gated on that open id existing, separately from `_reopen_admitted`, because the capacity gate can defer an admitted seat before `launch_seat` runs; collapsing those checks writes the reason onto the `done` row D54 forbids touching.
- The D66 brake is a coord.py-local count over this package's `sessions.csv` (`reopen_attempt_count`), not brief 07's `heart.db` counter. Unifying them would add a second concurrent SQLite writer into the live daemon's store — the shared-live-system risk the admission-wall comment exists to refuse. The local count also over-counts (no D52 progress-relief), so it can only over-brake.
- `reopen_downstream_seats` grants a flag, never an undo: it must not roll back, re-block, or rewrite any other seat's row. The durable home is a `messages.md` note plus a pointer suffix on the reason cell, not a second `sessions.csv` column (the downstream list is unbounded).
- `a554197b` (2026-08-23) changed how `--reopen` / `--rerun` / `--declare-only` launch on the daemon execution lane. A reader of `17d75459` alone will miss that; current daemon-lane behavior is in `server/20260823-i-lane-aware-launch-doors.md`.
