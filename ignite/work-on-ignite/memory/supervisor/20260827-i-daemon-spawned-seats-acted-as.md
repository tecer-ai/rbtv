## Observed
A daemon-spawned seat's every coordination act recorded `by ignite-daemon`, not the seat (live leader, 3/3 acts, 2026-08-27).

Every coordination act of a DAEMON-SPAWNED seat was filed under the daemon's name instead of the seat's. Measured live 2026-08-27 by the role-action-program `verify-rerun` seat (session `edd5c882`, evidence `role-action-program/fixtures/runtime-evidence.md` §RERUN, graded as CP-2 matrix row M7): a daemon-spawned `leader` ran its three end-to-end acts — `supervise instruct`, `supervise accept` and `coordinate send --record` — from its own sitting, all three succeeded, and all three recorded `by ignite-daemon`. The capability was never in question; the RECORD was wrong for every daemon-fired sitting, on every goal, since the daemon spawn path existed. Deployed tree and HEAD agreed: `COORD_AGENT` appears nowhere under `ignite/supervisor/**` except probes proving the daemon-side gate ignores it. D45's own 2026-08-20 note had already stated the same fact in passing — *"the daemon injects no `COORD_AGENT` for headless seats"* — as an observation, never as a defect.

## Mechanism
`composeCageFor` never emitted `COORD_AGENT`, so identity fell past an absent pane to the F16 lane's constant.

`coord/identity.py#resolve_agent` walks four rungs: `--as NAME` > `$COORD_AGENT` > the calling pane's registered roster row > the F16 daemon-exec lane. A daemon-spawned seat types no `--as` (it is a harness sitting, not a scripted call) and has no tmux pane, so rungs 1 and 3 are empty. Rung 2 was empty too, because `composeCageFor` (`ignite/supervisor/spawn/spawn.js`) — the ONE composer all three spawn doors go through, and the only place a seat's declarations become the environment of the process about to run — emitted PATH and declared credentials and never the seat's own name. So resolution fell to rung 4, `daemon_exec_identity()`, which answers with the constant `DAEMON_IDENTITY = "ignite-daemon"`. That lane is CORRECT for what it was built for (F16: give a daemon-fired `coord.py` exec an identity it does not have to claim) and is wrong as a seat's identity: it names the LANE, never the ACTOR, and it answers identically for every seat the daemon has ever spawned. The seat was never confused about itself; the log was — the same shape as G-111, arrived at from the opposite direction.

## Attempts
Not a first attempt — the injection was DELIBERATELY REJECTED once, and the rejection had to be re-examined before this fix could land. D45 (`70eb50de`, 2026-08-20, filed in `team-kit/20260821-c-caged-identity-corroboration.md`) rejected *"injecting `COORD_AGENT` at headless spawn (identity on an env var any local process can set — the same objection that killed the leader's original D43 proposal)"*, and D46 (`2138307d`) rejected *"an environment variable (forgeable)"* as identity outright. Both rejections were made to protect `_staff_claim_gate` (W3/D-2) — an AUTHORITY gate inside `resolve_agent` that refused an `--as <staff-chair>` claim unless the caller's identity was corroborated against a kernel measurable. That gate was DELETED on 2026-08-24 by `855f4290` (redesign batch D19 / T2-R10 / D24 / F-simplicity-7, filed as `team-kit/20260824-c-delete-staff-claim-corroborati.md`), whose own words are *"the ruling reclassifies a mismatched `--as` as an ordinary input error, not a security refusal"*. `--force` went with it (`149faf9a`). So `resolve_agent` today admits `--as leader` from anywhere with no corroboration at all, and the premise D45's objection rested on — that coord's identity resolution is a security boundary — no longer exists in the tree. The alternative that WOULD have honoured D45 literally, resolving the seat from `carrier_corroborated_seat` (`/proc/self/cgroup` → `rbtv-worker-<sid>` → the roster row keyed `sid:<sid>`), was considered and not taken: it resolves nothing before the seat has checked in, and it would re-grow inside `resolve_agent` a slice of exactly the layer `855f4290` deleted.

## Fix
Commit `8a4b7cab` (2026-08-27). A new one-line policy function `composeSeatIdentityEnv(seatPath)` returns `{ COORD_AGENT: seatPath.seat }`, and BOTH branches of `composeCageFor` call it — deliberately the same shape and the same reason as `composeSeatPath` beside it, so a later change to the identity policy cannot reach one branch and miss the other. The uncaged staff branch folds it into the returned `env` (before the `local-bin` branch, so the staff seat that declares no `local-bin` still gets its name — that early return used to yield a bare `{}`); the caged branch pushes `--setenv COORD_AGENT <seat>` onto the bwrap flag list, after `injectDeclaredEnv` so a credential declared under that name cannot displace it (bwrap takes the last `--setenv` for a name). Nothing else was touched: no door learned a new channel, because af326d61 already taught all three to carry `seatCage.env`, and the caged flag list already carried `--setenv`.

The value is `seatPath.seat`, derived by `parseSeatPath`/`parseServiceSeatPath` from the resolved workdir that has already passed the `workdir_root` containment gate and the launch-time materialized-seat check — the same derived-and-validated name this module already trusts for the tmux window name and for the whole cage composition. That is what makes it a SPAWNER STAMP and not an occupant assertion, and it is the classification the code already held: `supervisor/launch.py#identity_prefix` has always prefixed the tmux launch with `COORD_AGENT=<agent>` precisely so a seat *"never types its own name, and cannot mistype another seat's"*, and F17's key declaration in `supervisor/carrier.py` separates the two channels for this reason — `--as` YES (*"the one an arbitrary process can type"*), `COORD_AGENT` NO (*"injected BY this tool into every launched seat's own harness command"*). G-111's reasoning is that an ASSERTED identity must never outrank a VERIFIED one; here there is no pane and therefore no registered roster row to outrank, and the only rung displaced is a constant that names nobody. Rejected: making the emission conditional on a seat declaration (a seat cannot decline to be itself, and a declaration would make the log's correctness optional).
