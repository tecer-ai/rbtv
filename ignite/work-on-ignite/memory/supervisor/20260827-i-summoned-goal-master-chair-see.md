## Mechanism
Three independent enablers fired together.

(1) THE LANE. `coord/identity.py#SUMMONED_SEATS` has named `goal-master` a summoned chair since D24, and coord already refuses it two ways: `supervisor/ready.py`'s D24 branch answers `verdict: IDLE` ("ON-DEMAND summoned seat — NOT OFFERED"), and `supervisor/reconcile.js` excludes it from class B. The SEEDING half was missing, and coord's IDLE verdict could not supply it: `supervisor/ending-reads.js#readyFromEndings` rebuilds the frontier from the ENDING LEDGER and the `after` column, taking only `seat`/`after`/`seed` off coord's rows and reading no `verdict` field at all. `seeding.js#seedGoal`'s own note ("`ready` IS COORD'S ANSWER, HANDED IN — never derived here") was true of the transport and false of the answer. A root row with no `after` therefore reached `owed.js#deriveLaunchable` as state `ready`, entered class R, and was enqueued like any worker.

(2) THE VERB. `records.py#cmd_finish_goal` called `gate(args, "finish-goal")` for identity only — the per-verb role-gate layer was deleted whole on 2026-08-24 [T2-R10, D24, F-simplicity-7] and `gate()` is now a thin wrapper over `resolve_agent(required=False)`, so every resolved identity was admitted. And the sender was `args.as_agent or "leader"`: `--as` was absent (identity came from `COORD_AGENT`), so the literal fired and the append-only log recorded the end of the goal against a seat that had not run the command. That was the only `or "leader"` default left in the tree — `git grep -n 'as_agent or '` over `ignite/` returns exactly this one site.

(3) THE DESCRIPTOR. `meta/master/prompts/goal-master-prompt.md` §7 ("Execute owner-directed work, then disclose") tells the chair to do the work itself and carves out only "the thing asked for is the goal's own work rather than the owner's" — phrased as a reason to OUTSOURCE, not as a prohibition. Nothing in the file said the chair is not a planning role, and nothing barred a goal-ending verb.

## Fix
(1) The exclusion lands in `seeding.js#readySeats`, immediately after `readyFromEndings` — the ONE place the launchable set is derived, and the seam every consumer passes through (seeding's enqueue pass, `reconcile.js`, `operator/attached-execution.js`'s status verb, the probes). Excluding at each consumer instead would have minted four answers to one question. The list is read OFF COORD by `summonedSeats()`, which MOVED from `reconcile.js` into `seeding.js` and is imported back by it: `reconcile.js` requires `seeding.js` already, so this is the existing direction and no new module is created. Two readers of one list is the second source of truth D24's own note forbids, which is why the reader moved rather than being copied. A failed read yields the EMPTY set and logs — degradation is toward the old behaviour, never a silent hole. One `info` line, `chair <seat> is SUMMONED — not seeded (launched per owner message)`, fires once per (goal, chair) per process; a line on every 10 s pass is weather, not signal.

Rejected: hardcoding `goal-master` in `seeding.js` (the second list this program exists to remove); making `readyFromEndings` honour coord's `verdict` field wholesale (correct in principle and far wider than this defect — it would change how every IDLE/BLOCKED/STOPPED row is read by four consumers at once, and belongs in its own change).

(2) `cmd_finish_goal` gains a hand-rolled authority check reading the GOAL'S OWN REGISTER at call time: `taskforce_leader(pkg)` returns the seat `taskforce.csv` names `leader`, or None. Where a leader is named, any other identity is REFUSED on the `role gate` layer with a message naming who may fire it and what firing it does. Where the register names none (a package with no `taskforce.csv` — a team-kit run, a console package) it refuses nobody: there is no chair to gate against, and a goal nobody can end is a worse defect than the one being fixed. This is NOT a revival of the deleted role-gate layer — nothing here is a name predicate compiled into `gate()`; it is the shape `_secret_add_authority` (D49) already established for a per-verb authority that never went through `gate()`. The sender is now the RESOLVED caller, and an unresolvable identity REFUSES on the `identity` layer rather than stamping a literal.

(3) One bound added under §7 of `goal-master-prompt.md`, at the permission it qualifies rather than in a separate section: the chair is not a planning role (OQ-8, owner, 2026-08-26), its form is SUMMONED, and it NEVER performs the goal's contract, NEVER does a planning or execution seat's work, NEVER fires a goal-ending or completion-class verb, and NEVER carries an owner question out through a side channel. It closes with the positive statement — converse, route through the ask door, disclose — and with "an empty sitting on a chair nobody addressed is the correct outcome".

## ATTENTION
1. `readyFromEndings` STILL IGNORES COORD'S `verdict` FIELD. This fix removes the summoned names from the frontier; it does not make the frontier coord's answer. Any other per-row verdict coord computes (`STOPPED`, `BLOCKED`, the empty-disposition DEFECT arm) is likewise invisible to the seeding pass, which re-derives from the ending ledger. Do not read `seeding.js`'s "`ready` IS COORD'S ANSWER, HANDED IN" note as a guarantee — it describes the transport of the ROWS, not of the verdicts.
2. THE `finish-goal` GATE HAS A HOLE BY DESIGN: a package with no `taskforce.csv` names no leader, so ANY resolved identity may end it. That is exactly the shape of the 2026-08-27 channel-master defect (`scratch-seat-tool-inventory`: a seatless console-lane goal finished by the chair that created it). It is left open deliberately — closing it would make team-kit runs and console packages unfinishable — and is held shut on the descriptor side only.
3. A NEW ENTRY IN `SUMMONED_SEATS` NOW CHANGES FOUR BEHAVIOURS AT ONCE — readiness (`ready.py`), owed (`reconcile.js`), checkout outputs (`CONVERSATIONAL_CHAIRS`) and now seeding. That is the point of one list, but it means adding a name is no longer a local act: check every one of the four before widening it.
4. THE JOURNAL LINE IS PER-PROCESS, NOT PER-GOAL-LIFETIME. `SUMMONED_SAID` lives in the module, so a daemon restart says it again for every goal. That is deliberate (coord's list cannot change under a running daemon without a deploy, and a deploy restarts it) — do not "fix" it by persisting the set, and do not read a repeat as a second first-seeding.
5. `meta/master/prompts/goal-master-prompt.md` IS COPIED, NOT READ, into `<goal>/seats/goal-master/seat.md` at materialize time. Editing the prompt changes nothing for any goal already on disk. Six goals carry the pre-fix §7 today; a fix filed against the prompt is not deployed to a live chair until that goal is materialized again.
