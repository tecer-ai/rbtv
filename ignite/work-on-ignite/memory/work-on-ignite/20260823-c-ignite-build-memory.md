## Design
`fd93aa92` (2026-08-23T02:11:55Z, "feat(work-on-ignite): land per-component build memory") created the skeleton in one commit: the 19 BM-1 component folders under `ignite/work-on-ignite/memory/<component>/`, each with empty `_issues.md` / `_creations.md` / `_summary.md` ("No distillation yet — read the live index.") / `_issues-archive.md`; the then-root mechanics page `work-on-ignite.md` (148 lines); issue and creation templates; a 3-line `CLAUDE.md`; and this sample entry, first named `20260823-c-build-memory.md` with `commit: pending`. 81 files, 299 insertions.

Shape choices, each a rejection. Index plus one file per entry, not HISTORY's single running file (`parse_history` walking `## ` lines) — concurrent filers, git-diff noise, and the issue/creation split all break one append-only blob. The spec review (`review-of-m1-history.md`) reused Seen/Missed/Held names, the register-id cite, append-without-touching-bytes (`after2.startswith(after1)`), and `--repo` resolution; it dropped the single-file shape, the E11 path, the required `--id` against the live register, and the `history` verb. One write root (`ignite/work-on-ignite/memory/`), not eleven component dirs, so a caged seat can file without opening daemon code. Two kinds only: an issue is filed only when fixed; a creation covers something new, with `kind=change` for refactors, removals, and renames. Open items stay in the goal's `issues.md` / `loose-ends.md`. Every ignite-editing session — owner at a terminal included — reads before and files after; the command guarantees shape, the skill says when. Distillation is count-triggered (live index past ~60 lines → keep the last 30, rest to `_issues-archive.md`), run by `goal-memory-management`, not a calendar rotation. BM-3 frames it as box-② craft memory versioned with the code; the OPEN side stays in the `file-issue` register.

## How it works
`CLAUDE.md` and `AGENTS.md` are three lines: read `component.md`, then `references/work-on-ignite.md`, then read memory before and file after. `component.md` names the five entry points: the skill, the store, `file-issue memory`, `rbtv embed-search`, `goal-memory-management`.

Read, before editing component X: that component's `_summary.md` plus live `_issues.md` and `_creations.md` (and the same three for every other component the sitting will touch); `rbtv embed-search query` over `ignite/work-on-ignite/memory/` (ladder semantic → keyword → grep); grep of all indexes for the component names and paths about to be touched, as the deterministic floor; cite the consulted entry filenames in the proposal and the commit.

Write, after a fix or creation: `file-issue memory file` with `--component`, `--kind issue|creation|change`, `--title`, `--body-file`, `--commit`, `--deployed`, `--pin` (`--date` backdates, `--seeded` marks a backfill, `--components` lists the *other* components, `--attention` may repeat). `c80602d8` (2026-08-23T02:33:38Z) added `cmd_memory_file` / `cmd_memory_show` / `cmd_memory_rotate` / `cmd_memory_check` on `ignite/team-kit/file-issue.py` and declared the write root in `exposure.csv`. The command writes the entry, prepends the header block once, appends one ≤400-char index line (BM-2 grammar; backfills insert `seeded` after `kind`), and refuses a bad shape, a name over 30 characters, a missing field, or an unknown component. Indexes are newest-last and append-only. `memory show` prints a live index; `memory rotate` moves older lines past `--threshold`; `memory check` lints pairing, length, and fields; `memory relint` reports missing contract headings and placeholder phrases without gating. Pin may be NONE (must be visible). Files appear only as inline citations.
