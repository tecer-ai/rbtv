## Mechanism
`ignite/work-on-ignite/references/work-on-ignite.md` is a `method=skill` reference exposed to `leader`, `goal-master` and every other seat that edits `ignite/`. Its frontmatter carried `exposes-cli: [coord/file-issue, rbtv:core/rbtv-embed-search]`. `materialize-seats.py#resolve_cli_write_roots` (:4174, "W6 resolution variant B") walks seat → skill → CLI at GENERATION time to bake each seat's `--bind` write-roots into `seat.md`, and resolves each ref through `_ref_target` (:4036). A `rbtv:` ref is `rbtv:<path-under-the-repo>/<part>`, so `rbtv:core/rbtv-embed-search` resolved to component dir `<repo>/core/` and part-id `rbtv-embed-search`, then required a `method=path` row of that id in `<repo>/core/exposure.csv`. `d3a4dbf0` ("refactor(meta): the rbtv CLIs become meta components — rbtv-cli, teambuild, embed-search", owner ruling 2026-08-23) moved `core/capabilities/embed-search/` to `meta/embed-search/`, relocated its exposure row into the new per-component `meta/embed-search/exposure.csv` with a component-relative entry point, and **deleted `core/exposure.csv` entirely** — but swept no `exposes-cli:` referrer. The gate is a hard `raise Refuse` at :4212 with no `--force`/`--force-partial` arm, by design (a dead skill→CLI reference must not reach a materialized seat). The refusal is therefore correct behaviour over a stale declaration; the wrong value is born on the declaration line the move never updated. Both chairs, and only those, tripped it at the single-seat doors because the whole-workflow door catches per-chair refusals and downgrades them to warnings — the asymmetry that turned a hard stop into a silent leaderless goal.

## Fix
`578547a9` repoints the ref to `rbtv:meta/embed-search/rbtv-embed-search` — the CLI's real home, proven on disk (`meta/embed-search/tool/rbtv-embed-search` executable, answering `--help` exit 0) and in its own manifest (`meta/embed-search/exposure.csv` row `rbtv-embed-search,tool,path,rbtv embed-search,tool/rbtv-embed-search`). Three alternatives were rejected. Deleting the ref would have silently withdrawn the semantic-search write-root grant from every seat that edits `ignite/`, breaking step 3 of this very skill's own procedure, which REQUIRES the `rbtv embed-search query` pass. Weakening the gate to a warning was rejected as the exact asymmetry that produced the leaderless goals; the gate is right and the declaration was wrong. Adding a `--force` arm was rejected for the same reason and because it exists nowhere in the tool by deliberate design. `component.md`'s entry-point list dropped its now-false "(core's)" attribution in the same commit — docs-in-sync, and the line would otherwise send the next reader to a directory that no longer exists. The `exposes-cli:` sweep across `ignite/` and `meta/` found five declarations total and exactly one `rbtv:` ref, so no sibling remained dangling; the component's own `exposure.csv` row is unchanged because only the reference's frontmatter moved.

## ATTENTION
- The `exposes-cli:` chain is resolved by `materialize-seats.py` at SEAT-GENERATION time, not at spawn. Moving or renaming any CLI that a skill routes to therefore breaks seat CREATION, silently for chairs at the whole-workflow door, until the referring skill's frontmatter is swept. `grep -rn 'exposes-cli:' -A6 ignite/ meta/` is the sweep; there are only a handful of declarations and skipping it costs three days of leaderless goals.
- `rbtv:` references resolve against the rbtv REPO root and name a full path plus a part-id (`rbtv:<dir>/<part>`), so `rbtv:core/rbtv-embed-search` meant "part `rbtv-embed-search` declared in `<repo>/core/exposure.csv`", NOT "the core module's embed-search". A reader who parses it as a two-segment module/component ref will look in the wrong file and conclude the ref is fine.
- The whole-workflow materialize door DOWNGRADES a per-chair mint refusal to a warning and still exits 0. Any future chair-blocking defect will therefore be invisible to a caller that only checks the exit code — read the warnings, or check `taskforce.csv` for the chair rows.
- Goals materialized between `d3a4dbf0` (2026-08-24) and `578547a9` (2026-08-27) have NO `leader` or `goal-master` row and this fix does not backfill them. `supervisor/20260826-i-leader-chair-resolution-fell-b` now refuses the room rebuild on such a goal instead of promoting a worker, so they stay visibly broken until someone runs a materialize against them.
- exposes-cli: refs resolve at seat-GENERATION time — moving a routed CLI breaks seat creation until the referring skill's frontmatter is swept
