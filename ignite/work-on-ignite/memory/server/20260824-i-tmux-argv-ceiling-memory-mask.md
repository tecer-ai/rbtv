# 20260824-i-tmux-argv-ceiling-memory-mask — tmux argv ceiling: memory mask scaled with the host

kind: issue
component: server
date: 2026-08-24
commit: 02660b1a
deployed: no
pin: ignite/server/spawn/probes/probe-cage-argv-size.js

## Observed

Every tmux seat-door launch on this box died `E_CARRIER_FAILED: tmux new-window failed (exit 1): command too long`. Measured 2026-08-24 by `impl-cage-argv-ceiling` against HEAD of `ignite/core-redesign` in the `rbtv-redesign` worktree: `probe-tmux-seat-live` refused in 229 ms before any pane existed, and `probe-trace-header` T5 (the seat door) threw the same code while its at-dispatch siblings T1–T4 got as far as writing rows. Those were the residual two reds `20260824-i-envelope-launch-unresolved-goa` left behind when the `server/spawn` suite went 20/32 to 30/32, and that entry's own third ATTENTION bullet named this defect and its numbers while explicitly leaving it to launch custody. A clean `HOME` made the error disappear, which located the fault outside the cage's own logic. Not deployed — the redesign branch is `deployed: no` throughout.

## Mechanism

`cage.js#memoryMaskPaths` read `{home}/.claude/projects`, kept every entry holding a `memory/` subdirectory, and `composeAncestorMasks` emitted one `--tmpfs <dir>` per survivor. Bound (iii) of `r-seat-context-cut-at-launch-folder` drops auto-memory for every seat spawn, and the mask was written per-store because the comment in that function judged the harness's project slug "not knowable from here without reimplementing its derivation" — so it masked every store and let the derivation question go unanswered. The cost of not answering it is that the composed argv is proportional to how much unrelated work has happened on the machine: 696 stores and 68,503 bytes of argv measured here on 2026-08-24, growing with every new project directory the harness ever creates. Those flags ride inside `bwrap`, inside `systemd-run --scope`, inside the vector `tmux.js#composeSeatSpawn` hands `tmux new-window`, and tmux applies a command-length limit to the whole thing — measured on this box at roughly 16 KB (a 16000-byte command accepted, a 20000-byte command refused). The cage composed correctly; it simply could not be spoken. This is why universal caging turned it from latent to blocking: before every seat was caged, most launches never carried the mask at all.

## Attempts

First attempt held — checked: `git log ignite/server/spawn/cage.js` back through `6b55b1c4` (the D53/#576 `ro-mask` excuse, which touched `composeAncestorMasks` two lines above the memory loop and did not look at its cardinality), `92e7156c` (D48/D49, which introduced the `ro-mask` verb the memory loop deliberately does not use), and `21aed149`, whose ATTENTION bullet records the measurement and the decision not to fix it in that sitting. No commit before this one changed the memory mask's shape since it was written. The one thing that had been TRIED, and is not a fix, is avoidance: `server/spawn/probes/lib.js` roots every fixture at `/var/tmp` and `20260824-c-probe-fixtures-migrated-to-the` migrated ten fixtures to do so — that dodges the sibling `lastCovering` defect (`f6df6cae`), not this one, but it is the same habit of routing around the composer instead of fixing it.

## Fix

`02660b1a` masks the PARENT instead of the members. `composeMemoryMask(home, launchFolder)` emits exactly three mounts regardless of how many stores exist: `--tmpfs {home}/.claude/projects` (every store gone), `--bind {ownStore} {ownStore}` (the one store this launch folder keys on, back), `--tmpfs {ownStore}/memory` (bound (iii) applied to the own store too). The derivation the old comment declined to make is now made and verified rather than guessed: the harness names a project directory for the absolute launch path with every non-alphanumeric byte replaced by `-`, checked against the live store on 2026-08-24 (1794 entries, alphabet exactly `[-0-9A-Za-z]`, and known real paths transform onto real directory names). `launchFolder` is `resolvedWorkdir`, the same value `spawn.js` passes bwrap as `--chdir`, so the slug the mask computes is the slug the harness will use.

A CAP on the list was the obvious cheap alternative and was rejected outright: a truncated mask is a silent hole in exactly the surface bound (iii) exists to close, and it would have failed open on the busiest hosts. bwrap's `--args FD` mechanism was considered next and rejected on mechanism, not taste — tmux's SERVER forks the pane, so a descriptor opened by the daemon is not inherited, and the only way to hand bwrap an fd from a tmux command line is to wrap it in `sh -c` with a redirection, which `tmux.js`'s header rule forbids by name after run issue G-11. Masking the parent is better than either because it needs no new mechanism at all.

The own store is created (`mkdirSync`, recursive) BEFORE it is bound, and that ordering is load-bearing rather than tidy. `--bind-try` would have skipped an absent store silently and left the harness writing its transcript onto the projects tmpfs, where the next spawn could never find it — and `live-sessions.js` states that every live session is a `--resume`, so an ephemeral transcript is a seat that dies one tick later with nothing to resume. It is the same rule `21aed149` learned for `ensureGoalScratch`: the step that needs the folder is the step that makes it.

## Consequences

Isolation got STRICTLY STRONGER, and a probe's contract had to move to say so. The replaced mask hid `memory/` and left everything beside it open, so a caged seat could read the session `.jsonl` transcripts of every other project on the box — every conversation ever held there — for the sake of a `--resume` that only ever reads the seat's own store. `probe-ancestor-mask` leg (e) had encoded that as its assertion: it picked an ARBITRARY store, necessarily a foreign one, and required its transcript readable in-cage. That leg is retargeted, not relaxed — own transcript readable, own `memory/` empty, foreign store absent — and it fails if any of the three moves. `masked.memory` changes meaning from "number of stores masked" to "number of mask mounts" (0, 1 or 2); nothing asserted on the old meaning. `composeAncestorMasks` gained a `memoryStore` field naming the store it bound back, because a bind-back that silently missed is this bound's historical failure mode: it breaks `--resume`, not the mask, so nothing goes red. Two side effects are real and accepted: the composer now creates a project-store directory for whatever launch folder it is handed (probes included, which is why the new probe and leg (e) clean up after themselves), and bwrap mkdirs the `memory/` mountpoint through the bind, leaving an empty `memory/` in the own store. `bwrap.js#harnessStateBinds` still binds `~/.claude` wholesale, which spec-envelope §8 forbids and `impl-envelope-walls-suite` owns; this mask is what keeps that opening survivable meanwhile.

Removing the argv wall exposed two further defects that were hiding behind it, both pre-existing and both proven so by re-running with the memory mask neutralised on the pre-fix file. `probe-tmux-seat-live` now spawns its pane, passes the caps-at-kernel leg, and fails later because the seat cannot write its own folder: the compiler binds `{goal}/seats` RO from `daemon-owned-records.yaml`, and the `own-seat-folder-rw` punch-back that `20260824-c-plan-time-envelope-compiler` records as "launch punches `{self}`" was never built. `probe-trace-header` T1/T2/T5 all fail on `header-is-owners=false`, a `sessions.csv` header mismatch that fires at the at-dispatch door where no tmux is involved.

## Verification

`node ignite/deploy/probe-suite.js --dir server/spawn/probes` went 30/32 to 31/33 — every probe green except the two named above. `probe-cage-argv-size` is new and pinned: leg 1 composes the full tmux command against a synthetic home holding 1000 memory stores and asserts it under 8 KB (measured 1,587 bytes; the pre-fix composer produced 118,899 on the same fixture, past the real ~16 KB ceiling), leg 2 pins the flag count at seven and the byte delta between 10 and 1000 stores at zero, leg 3 proves the isolation contract against a real `bwrap`, leg 4 holds the absent-path discipline. `probe-ancestor-mask` is ALL PASS with the retargeted leg (e). `probe-tmux-seat-live` no longer throws `E_CARRIER_FAILED`; `probe-trace-header` T5 went `threw=E_CARRIER_FAILED` to `threw=null` with a real `pid-starttime`. Deployed: no.

## ATTENTION

- Never re-express this mask as a per-store list, and never cap one. The argv is spoken by `tmux new-window`, which refuses a command over roughly 16 KB, so a list that scales with `{home}/.claude/projects` fails only once the HOST gets busy — the defect is invisible on a fresh box and total on a worked one. `probe-cage-argv-size` leg 2 pins the flag count at seven for this reason.
- `composeMemoryMask` CREATES the own store before binding it. Switching that `--bind` to `--bind-try` and dropping the mkdir looks like removing a side effect, but it silently sends the harness's transcript to a tmpfs that dies with the namespace, and every live session is a `--resume` — the seat dies one tick later with nothing to resume, and nothing goes red at launch.
- The project slug is `path.normalize(launchFolder).replace(/[^A-Za-z0-9]/g, '-')`, and it is the harness's derivation, not ours. If the harness ever changes it, the bind-back misses, resume breaks quietly, and the MASK still holds — so this fails safe but silent. Re-verify the alphabet against `{home}/.claude/projects` before trusting a report that resume is broken.
- `probe-ancestor-mask` leg (e) asserts foreign-store ABSENCE now. Restoring its old shape (an arbitrary foreign store's transcript readable in-cage) reopens every other project's conversation history to every caged seat.
- The two probes still red after this fix are NOT this defect and are not in cage custody: the own-seat RW punch-back (`own-seat-folder-rw`, unbuilt, `probe-tmux-seat-live`) and the `sessions.csv` owner-header mismatch (`probe-trace-header` T1/T2/T5, which fires with no tmux in the path). Both were proven pre-existing by re-running the suite with this mask neutralised on the pre-fix file.
- Never re-express the auto-memory mask as a per-store list or a capped one — the argv is spoken by tmux new-window (~16 KB ceiling), so it fails only once the HOST gets busy.
