## Mechanism
`resolveLocalBinGrant` ro-bound the whole host `~/.local/bin` onto PATH undifferentiated; `~/.local/bin/stools` is a real symlink into `3-resources/tools/stools/stools.py`, and `read-root: true` gives the same reachability by full path. Neither grant carries `grantClass: 'exposedCliCode'`. `private-scope.js` TIER 2b only pierces a masked path (`config.yaml`, `credentials/`) for an opening tagged that grantClass — i.e. only a seat that declared the tool via `exposed-clis:`. An undeclared-but-reachable seat therefore ran the real executable against its own secrets still bound to `/dev/null`-like device nodes (the live cage showed `config.yaml` as char device 1:3), and Python's `PermissionError` bubbled three stack frames from the actual mistake (no declaration). No invocation-time refusal existed: the only `REFUSED` strings were declaration-time (`exposed-clis entry REFUSED`) and pierce-time (`private-scope pierce REFUSED`).

## Fix
`7f6eaf3e` (2026-08-22, "D56/D74 clause 1") adds `private-scope.js#needsDeclaration(workspaceRoot, dir, log)` — generic, no tool name hardcoded — which answers whether a candidate directory holds, lies inside, or is a private entry by the same deny-list + pattern-floor every other tier of that file reads, scoped to the workspace only. `spawn.js` writes one shared `/bin/sh` script (`REFUSAL_SHIM_BODY` → `os.tmpdir()/rbtv-cage-refuse-shim.sh`) that echoes `"$name is not exposed to this seat — declare it in the exposed-clis: frontmatter (seat.md) to use it."` keyed off `$0`'s basename, so one file services every refused name in every cage. In `composeCageFor`, every name in the real `~/.local/bin` not already in `exposed-clis:` is classified; if `needsDeclaration` says its directory holds anything private, the PATH-builder `--symlink`s the shim over that name into `.rbtv-bin` ahead of the real `~/.local/bin` (same shadowing order as declared tools). A name needing no pierce (`coordinate`, `teamview`, `scaffold-seats` — the original reason `local-bin` exists) stays unshimmed. `resolveExposureEntryPoint` walks `.rbtv/mirror/**/exposure.csv` for a `part-id` match, restating `materialize-seats.py`'s `ws:`-prefix rule in JS, because `realpathSync` alone misclassifies a wrapper script: live `gtools` is `#!/bin/sh … exec /real/path/gtools.py "$@"` sitting directly in `~/.local/bin`, so its realpath never reveals the code tree. D74's design constraint — the mechanism must work for any seat granted a tool, not only masters — is why classification is generic and the shim applies to the whole `local-bin` set rather than a stools-specific patch. Rejected: wrapping stools/gtools' own `load_config` with a friendlier error (would miss `sd-graph`'s floor-pattern class and every future tool). D56's other two arms (masters declare stools; `secret-add` / G-123) are out of this entry.

## ATTENTION
- S2-control in `probe-master-cage.js` is a deliberate negative test: it asserts the undeclared master did not print `CFG_OK` and did not exit 0. It does not assert the named-refusal string — the control invokes `python3 …/stools.py` by full path, which bypasses the PATH shim and hits the old masked-path crash. A pass for the wrong reason (the tool erroring before the mask) is false confidence that declaration is what makes S2 work.
- `needsDeclaration` returns false unconditionally for any path outside `workspaceRoot`. A host utility (`claude`, `codex`, `uv`) is never shimmed, by design. A future private tool installed outside the workspace tree silently bypasses this refusal.
- `gtools` is code-identical to stools at parser-build but had 0 log hits and was never run end-to-end post-fix (OAuth, not run to avoid a network call). The generic shim should cover the wrapper-script case via `resolveExposureEntryPoint`; nobody verified live `gtools` after that resolver landed.
- The live `sd-graph` symlink in `~/.local/bin` pointed at `1-projects/rbtv-sb-merge-refactor/…`, which differs from the exposure.csv entry `ws:1-projects/build-ignite/system-definition/CLIs/sd-graph/scripts/graph.py`. That drift can make `needsDeclaration` / `resolveExposureEntryPoint` classify different directories; it was not re-checked after the fix.
- The PATH shim does not cover `read-root` full-path invocation. A seat with `read-root: true` and no declaration can still run `python3 …/stools.py` and hit the raw `PermissionError` — S2-control is that shape on purpose. A tool reachable only by full path, or `component-lint`'s exec-time symlink EACCES, is a different signature this fix did not close.
