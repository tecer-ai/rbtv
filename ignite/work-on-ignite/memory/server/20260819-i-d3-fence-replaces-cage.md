## Observed

On 2026-08-19 the root-cause archaeology (`redesign-plan/seed/root-cause-archaeology-2026-08-19.md`) measured the bwrap cage as the top enabling cause of six freezes in ten days, in two independent ways. Write denial: a caged seat hitting EROFS on a ledger write, then routing around it — ≥8 instances across 3 goals in 6 days; 97% of meet's disposition writes were by the out-of-cage closer (~21s lag), not the seat. Concrete hits: 08-13 every planning seat FAIL-BLOCKED because the cage missed declared context paths and `sessions.csv` was EROFS, with FAIL-BLOCKED recorded as `done` so every surface read healthy; 08-18 15:36 mint's engine-half write hit EROFS, swallowed as `False`, and the leader sat 2h37m with unread mail. Observation denial: daemon-lane seats launched with `--unshare-all --proc /proc`, so in-cage `/proc` showed only the seat's own processes; `coord.py`'s chair-liveness predicate (`sessions_sitting_id` → `ident_is_live_process`) therefore read every other seat as dead, structurally, always — which is why the 2026-08-15 mid-sitting wake fix (`05490c92`) was inert for every caged caller. The same morning the owner ruled the threat model (`redesign-plan/seed/ignite-redesign-alignment-2026-08-19.md` §3): agents writing in repos that are not `goals/`; rogue writes inside the goal folder and record forgery are explicit non-concerns. The `thin-fence` seat shipped the code that evening.

## Mechanism

`buildBwrapArgv` in `server/spawn/bwrap.js` composed `--unshare-all` (then `--share-net`). `--unshare-all` includes a PID namespace; with `--proc /proc` the seat saw pid=2, ancestry 2←1, never a host pid. Any in-cage `ident_is_live_process` walk was therefore a guaranteed miss, so a caged wake bound the last-ENDED session (archaeology §1 steps 1–3). Independently, `cage.js` treated `sessions.csv` as identity ground truth and ran `assertGroundTruthUnwritable` over the composed spec — last covering RW opening wins — throwing `E_CAGE_GROUND_TRUTH` if any `bind`/`bind-try` left that file writable. `composeCageFor` in `spawn.js` called that assertion, the service-seat branch appended a `ro-bind:{seatDir}/sessions.csv` template line, and `resolveGoalsWriteGrants` paired every other-goal write grant with a `goalsWriteGroundTruth` carve that put that goal's `sessions.csv` back to read-only. The goal folder itself opened as a parent `ro-bind` plus per-ledger `bind-try` holes. A seat that must write the ledger it is required to write therefore hit EROFS; each new side-channel (store, write-hole, out-of-cage closer) was the only remaining path. The two defects share one design: the cage's job was anti-forgery and process isolation, and those jobs denied the observation and the writes the seats needed.

## Attempts

The write-half was patched without dropping the cage. `46780c1a` (2026-08-15) opened `{goalDir}/settings-requests` RW in SeatBinds because the master-profile request inbox was EROFS — one more narrow hole. `3acc353e` (2026-08-15) made the registry splice keep its inode so a cage's single-file bind would survive a rewrite, working around the bind rather than the design. `60058a85` (2026-08-18) made the check-out EROFS warning name its fallback chain; `c955c578` (same day) stopped a half-written wake grant reporting success. Archaeology §3.3 names the pattern: each instance closed by a new side-channel, never by resolving "seats must not forge the ledger" vs "seats must write the ledger." No commit before `ac4726a6` dropped `--unshare-all` or PID-namespace isolation (checked: the four EROFS subjects above, plus `git log` on `bwrap.js`/`cage.js` for an unshare rewrite — none). Archaeology §6 scored "replace with worktree per goal" as not supported as stated — a worktree fixes file isolation, not identity/anti-spoofing or `/proc` observation — and recommended keeping isolation and routing ledger writes through a 13th gateway intent. That alternative was not built; D3 overruled it by dropping the anti-forgery goal.

## Fix

D3 (`redesign-plan/decisions.md`, 2026-08-19) rules the sandbox as a thin fence + git worktrees: protect everything outside `goals/`; record forgery is a NON-goal; allow-list is worktree branches rw, goal folder + artifacts rw, own seat folder rw except `seat.md`, `rbtv/` + `.rbtv/mirror/` read, coordination ledgers writable, env/secret files simply absent; no file-level ro-binds of records, no PID-namespace isolation. D8's bar is "a solution that works"; some sandbox risk is accepted (alignment §3: simplicity over completeness). Worktrees alone were rejected because they do not stop arbitrary shell writes elsewhere — the owner accepted that challenge, so the fence remains a reduced bwrap allow-list on top of worktrees, not worktrees instead of bwrap. Gateway-intent ledger writes (archaeology §7.4) were rejected because they keep the anti-forgery job D3 deletes.

`ac4726a6` (2026-08-19 20:45:35Z, `feat(spawn): replace the cage with the D3 fence`, 14 files, +370/−466) is the mechanism change. `buildBwrapArgv` replaces `--unshare-all` with `--unshare-user` / `--unshare-ipc` / `--unshare-uts` / `--unshare-cgroup` (PID ns dropped; cgroup unshare kept until F-6). `assertGroundTruthUnwritable` and `E_CAGE_GROUND_TRUTH` are deleted. The template collapses to one `bind:{goalDir}`; the only remaining file-level RO binds are wall-control surfaces (`seat.md`, `coordination/permission-edits.csv`), not records. `composeCageFor` stops asserting ground-truth and stops appending the sessions.csv carve; `resolveGoalsWriteGrants` drops `goalsWriteGroundTruth`; new `resolveFenceReadGrants(seatPath)` adds the two D3 item-4 READ grants (`rbtvRoot`, `rbtvMirror`). `cagespec.py` mirrors the comment change and the DROPPED_GRANTS swap. `config/spawn-profiles.yaml` lost 170 lines of per-ledger holes. `e37853b2` (15 seconds later) writes `ignite/CLAUDE.md` § "The fence (D3, 2026-08-19)" so the tree describes the fence, not the cage. `fb8db289` (21:21:53Z) retargets two engine probes that `ac4726a6` reddened because it only swept `server/spawn/probes/*`.

## ATTENTION

- Re-adding `--unshare-all` or `--unshare-pid` to `buildBwrapArgv` reintroduces the exact liveness-blindness D3 removed: in-cage `/proc` again shows only the seat, and `ident_is_live_process` again reads every other seat as dead. The missing PID namespace is deliberate (D3/D8); `ignite/CLAUDE.md` says do not build a mitigation for host-process visibility.
- The two remaining file-level RO binds (`seat.md`, `coordination/permission-edits.csv`) are wall-control surfaces — the fence holding its posts — not a revival of `assertGroundTruthUnwritable`. Treating them as anti-forgery will misread every later grant line.
- This commit is the fence's origin. Later spawn entries (`20260821-c-truly-everything-master-cage`, `20260821-i-stools-undeclared-tool-refusal`, `20260822-i-ro-mask-private-scope-fix`) are the current shape; edit those, not this allow-list, when changing what a seated process can touch.
- F-6 / D46 (`2138307d`) is a related identity defect (stale OPEN-row selection, then dropping `--unshare-cgroup`), not a regression of this PID-namespace change. Do not restore a namespace to "fix" fence identity.
- Env/secret files stay unbound (D13). `ticker.js` hardcoding `envFile: null` was still open at `e37853b2`; wiring a tool-declared env file is ticker custody, not a fence hole to close by binding the file in.
