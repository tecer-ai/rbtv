## Observed
Any seat whose `seat.md` declares `exposed-clis:` refused at spawn, before any process was born, on the redesign worktree (`/home/henri/ht-wkdir/second-brain/5-workbench/rbtv-redesign`, branch `ignite/core-redesign`; deployed tree unaffected). Surfaced 2026-08-24 at HEAD `9da3db34`, immediately after the own-seat punch (`c3ceb005`) unblocked live caged launches far enough for the branch to be reachable, and named in advance by the ATTENTION of `20260824-c-envelope-launch-refuse-and-inj` ("do not re-run `conflictBind` over a compiled bind list") and again in the Consequences of `20260824-i-envelope-launch-never-punched`, which recorded it as NOT fixed there and out of that seat's custody. Measured directly rather than inferred: driving `seat-grants.js#conflictBind` over a REAL `admitLaunch` bind list plus one exposed-CLI code dir returns `conflict` on the pair `ro:template-family:{ws}` vs `rw:template-family:{ws}/.rbtv/goals/g1` — a pair the compiler itself emitted and admitted.

## Mechanism
`spawn.js#composeCageFor`, in the `exposedClis.length > 0` branch, mapped `admitted.binds` down to `{path, access, source}` and handed them to `seat-grants.js#conflictBind`, which flags any covering pair at different access with no carve rules at all. That is the right predicate for the legacy grant arrays it was written for (`composeSeatCage`'s 14-source stack, where every entry is a flat grant), and the wrong one for a COMPILED bind list, whose legitimate shape is nested by design: family 5 `vault-wide-read` binds `{workspace}` ro, family 3 binds `{goal}` rw inside it, `daemon-owned-records` binds `{goal}/seats` ro inside that, and since `c3ceb005` the own-seat punch adds `{self}` rw inside THAT with `{self}/seat.md` ro inside it again. Every one of those adjacencies is a carve the compiler authorized at compile time and then re-authorizes on demand through `compiler.js#authorizedCarve`; asked without that function, the very first pair in the list answers "conflict". Worse, the map dropped `family` and `origin`, so even a carve-aware caller reading that array could not have answered the question — the same decoration-looks-unused trap `f6df6cae` recorded for `bindsToSpec`. The branch is entered only when a seat declares an exposed CLI, which is why the defect was invisible while `probe-tmux-seat-live`'s fixture seat (no such declaration) was the only live launch anyone drove.

## Fix
`spawn.js` gains `exposedCliConflict(sources)` — the same pairwise loop and the same `{kind:'conflict', path, pair}` refuse value as `conflictBind`, with one added line: a pair at differing access whose paths differ is skipped when `compiler.js#authorizedCarve` authorizes it. The call site now carries `family` and `origin` through from `admitted.binds`, exactly as `bindsToSpec` does, because the carve question is unanswerable from `{path, access}` alone. `conflictBind` is no longer imported by `spawn.js`.

Importing the compiler's predicate rather than teaching `conflictBind` about carves was chosen because `conflictBind` is also driven, unchanged, by `envelope-launch.selftest.js` and remains correct for legacy flat grant arrays; and because `seat-grants.js` is a spawn-family file a concurrent seat was editing, so the change belongs where the defect is. Rejected: deleting the check outright (the exposed-CLI cover refusal is `c9615ca2`'s posture and a real wall — a CLI's code tree mounted ro inside an opening the envelope holds rw hands the seat two answers about one path); moving the whole check into `launch.js` so the compiler sees the exposed CLIs (the exposed-CLI grants are read from `seat.md` at spawn, and the compiler is per-goal and plan-time by design — the division `20260824-c-plan-time-envelope-compiler` records); and filtering the bind list down to "just the exposedCli pairs" before calling `conflictBind`, which answers the right question by accident and stops answering it the moment a genuine bind-vs-bind conflict appears.

Refuse posture is unchanged for genuinely unauthorized mixes, and structurally so rather than by assertion: exposedCli entries carry no `family`/`origin`, so `authorizedCarve` finds nothing to authorize on any pair involving one, and the identical-path case never carves in either spelling.

## Consequences
The pre-existing false refusal is gone: a seat declaring `exposed-clis:` composes its cage over the standard goal binds. `spawn.js` gains a direct dependency on `ignite/envelope/compiler.js`, the same `server/spawn` -> `envelope` direction `cage.js` took at `f6df6cae` and `spawn.js` already travels for `launch.js`, `credentials.js` and `stamp.js`; no cycle, since `compiler.js` reaches only `load-config.js` and `paths.js`. `exposedCliConflict` is exported for the probe. `conflictBind` itself is untouched and keeps its remaining consumer (`envelope-launch.selftest.js`); with `spawn.js` off it, `seat-grants.js` is now the legacy-array predicate only, and a future compiled-bind-list caller must import `authorizedCarve` rather than reach for it. `probe-envelope-walls` grew leg 10 and now requires `../spawn`.
