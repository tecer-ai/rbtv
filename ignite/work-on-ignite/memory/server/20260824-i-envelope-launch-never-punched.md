## Observed
Every caged worker seat spawned, passed its caps-at-kernel leg, and then could not write the one directory it exists to fill. Measured 2026-08-24 at HEAD `16fdc15f` on the redesign worktree (branch `ignite/core-redesign`, deployed tree unaffected): `node ignite/server/spawn/probes/probe-tmux-seat-live.js` reached `legA caps-at-kernel PASS: memory.max read from the HOST kernel … == declared 384M`, and then died `assertion failed: the live seat wrote its report into its workdir (proves it ran AND that the grant works)` — the live tmux seat never produced `a4-report.txt` in `/var/tmp/a4-live-*/work/.rbtv/goals/a4goal/seats/a4seat`, its cwd and the only path the profile grants. Suite verdict `server/spawn` 31/33 with `probe-tmux-seat-live` red on that leg.

## Mechanism
The envelope compiler binds `{goal}/seats` `ro` as a daemon-owned DIRECTORY (`daemon-owned-records.yaml` `directories: [coordination, seats]`), which is what stops a worker writing a peer's folder. spec-envelope §5 excepts exactly one thing from that cover, in the heading of the directory table itself — "the dir and everything under it, except a worker's need to write its own seat folder" — and the file records the exception as `own-seat-folder-rw: true`. Nothing consumed that key. `compiler.js#compile` is per-GOAL and plan-time: it is handed workspace/goal/rbtvRepo and never learns WHICH seat is launching, so it cannot spell `{self}` and correctly does not try (`20260824-c-plan-time-envelope-compiler` records the division: "launch punches `{self}`"). `launch.js#admitLaunch` — the consumer that does know — returned `compiled.binds` untouched, and `composeCageFor` did not even pass a seat identity into it (`workspaceRoot`, `goalId`, `goalDir`, nothing more). So the seats tree went to bwrap wholly read-only and every worker got EROFS on its own folder. The punch was declared in config, recorded in memory, described in the spec, and implemented nowhere.

## Attempts
First implementation of the punch — checked `570131d9` (the compiler, which deliberately left it to launch), `c9615ca2` (`launch.js` at birth: no seat identity on the `admitLaunch` input at all), `21aed149` (the previous launch.js sitting, which fixed compile ORDER and the 11 GB shim copy and did not touch grants), `02660b1a` / `f6df6cae` (the cage-argv and `lastCovering` fixes that unblocked the live probe far enough for this defect to become visible), and spec-envelope §5. The nearest prior art is the OPPOSITE direction: `92e7156c` (D48) made the peer-seats overlay refuse writes instead of discarding them via `ro-mask` + `punchMaskSource()`, and `6b55b1c4` (D53/#576) then had to excuse `ro-mask` covers in `private-scope.js#visible()` because a pattern-floor match nested under a read-only cover killed the spawn at bwrap `mkdir`. The envelope model replaced that verb with a plain `ro` bind and lost the punch with it.

## Fix
`launch.js#ownSeatPunch(binds, raw)` adds ONE rw bind at compose/launch time and refuses to add a wider one. Guards, each of which is the point rather than defensive noise: the punched path must resolve (an unresolvable own seat folder is a `{kind:'unresolved', source:'own-seat'}` refuse, holding the compiler's own line one layer out, because the quiet alternative is a silently read-only launch — this defect); its PARENT must be exactly the launching goal's realpathed `{goal}/seats`, so a peer goal's seat, a nested path under the own folder, and a service seat whose home IS the goal dir all punch nothing; something covering it must already be `ro`, so on a list where the tree is already rw the punch is not a redundant argv line; and a path already on the list is not duplicated. The result is re-sorted with the compiler's own comparator rather than appended, because bwrap applies mounts in argv order and the last one wins: the list must read `{goal}` rw → `{goal}/seats` ro → `{seatDir}` rw → `{seatDir}/seat.md` ro, and an appended punch would remount the seat folder OVER the daemon-owned `seat.md` carve inside it and hand the worker a writable `seat.md` — the one file §5 keeps read-only inside an otherwise RW own folder. `compiler.js#authorizedCarve` gains the pair (`narrow.origin === 'own-seat' && wide.origin === 'daemon-owned'`) so the single source of truth for "is this covering pair a conflict" knows about the exception; without it `cage.js#lastCovering` refuses any seat whose private-scope pattern floor matches a path under its own folder, which is the D53/#576 shape one layer in. `spawn.js#composeCageFor` passes `seatDir: seatPath.seatDir`. Rejected: teaching `compile()` a seat argument (it is per-goal and plan-time by design, and the compiler entry's ATTENTION forbids growing this hook there); labelling the punch `origin: 'daemon-owned'` to reuse the existing carve rule without touching the compiler (it would make the grant unreadable in the bind list and in any refuse pair); punching `{goal}/seats` rw and re-masking peers (a widening the spec's one-folder exception does not authorize).

## Consequences
Worker bind lists grow by exactly one entry when a `seatDir` is supplied; a call without that field composes exactly as before, so `compilePlanning`, the register door and the ancestor-mask probes are unchanged. The punch is `origin: 'own-seat'` / `source: 'own-seat-punch'` on the bind list, and both `lastCovering` and any refuse pair now name it. `probe-envelope-walls` grew legs 7-9 (the punch, its three boundaries, its refuse). NOT fixed here, and now one pair louder: `spawn.js`'s `conflictBind` over `admitted.binds` in the `exposedClis` branch has no carve rules at all, so it already reads the pre-existing `{goal}` rw / `{goal}/seats` ro pair as a conflict and refuses any seat with an exposed CLI — the trap `20260824-c-envelope-launch-refuse-and-inj` names ("do not re-run `conflictBind` over a compiled bind list"), owned by `impl-envelope-walls-suite`, untouched here by custody.

## ATTENTION
- The punch must stay SORTED into the bind list, never appended. bwrap's last mount wins, so an appended `{seatDir}` rw remounts the seat folder over the daemon-owned `{seatDir}/seat.md` ro carve and quietly makes `seat.md` writable — leg 7 asserts the index order, not just the accesses, for exactly this reason.
- Never widen the parent test. Punching whatever `seatDir` the caller hands over turns a one-folder exception into a grant source: the field comes from `seatPath`, and only a DIRECT child of the launching goal's own realpathed `seats/` is `{self}`.
- An unresolvable own seat folder is a refuse on purpose. A silent skip is precisely how this defect presented — a seat that spawns, passes every cap and absence leg, and then cannot write anything.
- `authorizedCarve` is the ONE place that answers "is this covering pair a conflict"; the own-seat rule belongs there and not in a second spelling inside `cage.js`, which is the drift `f6df6cae` already had to undo once.
- `spawn.js#conflictBind` in the `exposedClis` branch still has no carve rules and reads the compiled goal-folder/daemon-owned pair as a conflict. It is not this fix's regression and not this seat's custody, but a seat with an exposed CLI still refuses at that line.
