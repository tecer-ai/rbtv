## Observed

The CP-1 inventory of the role-action-program (`1-projects/build-ignite/build/role-action-program/fixtures/matrix.md`, 2026-08-26) measured that the master component's own written material told its three seats things that were false against the deployed code. Six distinct classes, all read-only reproduced on the console that day: (1) `master-instruments.md` §"Who is working" mandated `teamview`, a tool deleted on 2026-08-24 in `549a0f8b` — `teamview --help` → `No such file or directory`, reproduced inside a live sitting (`406c8cce`); (2) three full paths in the same file pointed under `ignite/capabilities/…`, a tree whose tracked files moved to `ignite/operator/…` (`git ls-files ignite/capabilities | wc -l` → 0); (3) the bus section granted a "roster" leg and a standalone WAKE the CLI does not carry (`coord.py wake --help` → `invalid choice: 'wake'`; the roster verb is `workers`); (4) `master-bootstrap.md` §3 ordered `rbtv goal materialize` in the exact state where that verb refuses; (5) both master prompts promised "Secrets stay UNREADABLE (… are masked)" while the masking code sits behind the sandbox return these uncaged seats never reach; (6) `channel-master-prompt.md` said twice that this seat does not file defects, while its own seat-folder rules say it files and a live sitting had filed one. Deployed and HEAD did not differ on any of these — the material is read from the repo tree at assembly, and the branch `ignite/core-daemon` carried the same text as the rendered descriptors.

## Mechanism

Every one of the six is the same class: the master's written material is a SECOND statement of a fact the code already holds, and nothing re-derives it when the code moves. `teamview`'s deletion entry (`20260824-c-delete-team-monitor-cli-and-te`) says so in its own ATTENTION 2 — that sweep fixed only the load-bearing references its DoD grep targeted and left the prose. The path breakage is the same shape after the capabilities→operator move. The bootstrap self-contradiction has a sharper cause: §3 was written when "the materialize command" was believed to create the goal's seat tree from a pre-placed plan workflow, but `cmd_materialize` (`ignite/operator/goals-tree/tool/goal_cli.py:2885-2891`) opens by reading `taskforce.csv` and raises `absent — nothing to materialize` when it is missing — and a bootstrapped goal is DEFINED by having no taskforce. The only writer of that file is `materialize-seats.py`, whose own `--help` reads "seat descriptors first, then taskforce.csv rows", reached as `scaffold-seats --workflow`. So §3 ordered the one command guaranteed to refuse, and its "Creating what is missing under the goal folder IS materialization, done by the command itself" sentence told the reader the refusal could not happen. The secrets sentence is the same second-statement failure across a code path: the composed private read scope lives after the uncaged early return in `spawn.js`, so the promise was true of a caged seat and false of every seat that actually reads it.

## Attempts

First attempt held for the bootstrap contradiction, the wake/roster wording, the secrets sentence and the filing clauses — checked: `git log --oneline -- meta/master/references/master-bootstrap.md` shows no prior correction of §3's command choice, the CP-1 matrix §6 records the re-checks that first established each of these as live rather than stale-inventory, and `1-projects/build-ignite/build/role-action-program/decisions.md` carries the owner's rulings of 2026-08-26 as the first ruling on each. The `teamview` and path classes DID have an earlier partial attempt: `549a0f8b` (2026-08-24) deleted the tool and swept its load-bearing callers but deliberately left prose mentions, disclosing them as a loose end in its own ATTENTION 2 — that is why the prose survived three days into a live sitting's refusal.

## Fix

One commit (`052b0042`) over ten files, applying the owner's CP-1 rulings rather than the builder's judgment. `master-instruments.md`'s "who is working" section now names two LIVE reads instead of a deleted renderer: `ignite status` / `ignite inspect …` for what is running system-wide, `coordinate workers` for who is alive inside one goal, `acct` for quota — chosen over building a successor renderer (owner ruling OQ-6 option (a)) because both commands already return the data and are maintained. The three stale paths were repointed at `ignite/operator/…`, each `ls`-ed before it was written. The bus section drops the standalone wake entirely: `coordinate send --help` says it wakes the recipients' panes as part of sending and that "wakes are best-effort, the log is the truth", so a seat told to report "a failing wake" was being handed a duty with no verb behind it (OQ-23 option (a)).

`master-bootstrap.md` §3 was rewritten to order `scaffold-seats --package <abs> --workflow <plan workflow> --catalog-root <root>` and to state explicitly that `rbtv goal materialize` is the `goal-materialize` step over an EXISTING taskforce, citing the refusal and its line so the next reader can check rather than trust. §5 gained the OQ-22(b) ruling — nothing is queued; a goal advances on its lane — and the same correction was carried to `tasks/serve-master-traffic.md`, which is the SOURCE of the "that goal's job is queued 10 minutes out" clause the rendered `_channel-master/seat.md` carries at :229/:250. Striking only the rendered copy would have been undone by the next re-render; that is why the task file and `component.md`'s two live claims were amended in the same change even though the ruling named the descriptor.

The false secrets sentence was struck from both master prompts and replaced with an honest bound — nothing masks secrets for you, so never read one; additions only through `secret-add` — taking OQ-26 option (b) over option (a) (compose a real private scope) because composing one on the uncaged spawn path is security work with its own design, and leaving option (c) would keep three seats believing a guarantee that would make them careless. The separate, newer "Secrets remain unread and un-updated: append-only via `secret-add`" procedure lines were deliberately NOT touched — that mediated-append design stands.

Exposure changes: `master-instruments` added to `goal-master-prompt`'s `exposes: skill:`; the two goal-creation references (`master-scaffold-flow`, `master-bootstrap`) removed from it, with its creation-ordering prose aligned to D2 (creation is the channel-master's and console-master's door); `ignite/coord/file-system-issue` + `ignite/coord/file-issue` and `core/coding/commit` added to `channel-master-prompt`, each with a `<resources>` bullet so `component-lint`'s resources-coverage check is satisfied and the occupant has prose on when to reach for it. `meta/leader/prompts/leader.md` was corrected on one granted line: `route-fail` is a `supervise` verb, not a `coordinate` one.

## ATTENTION

- `rbtv goal materialize` and `scaffold-seats` are NOT interchangeable and reading them as one verb is what produced the bootstrap dead end. `materialize` reads `taskforce.csv` first and refuses when it is absent (`goal_cli.py:2885-2891`); `scaffold-seats --workflow` WRITES that file. Any prose that says "the materialize command creates the seat tree from the plan workflow" is describing a command that does not exist.
- The master's written material duplicates facts the code owns, and NOTHING re-derives it. A tool deletion or a component move must sweep `meta/master/references/**`, `meta/master/prompts/**` AND `meta/master/tasks/**` in the same change — `549a0f8b` swept the code callers only, and the prose it left cost a live sitting a refusal three days later.
- A ruling that names a RENDERED descriptor (`.rbtv/goals/**/seat.md`) is almost never fixable there: the text comes from `meta/master/prompts/*` and `meta/master/tasks/*` at assembly, so a strike applied only to the rendered file is undone by the next re-render. Fix the source in the same change and say so.
- Changing a reference's frontmatter `description:` obliges the matching `exposure.csv` row in the same commit — the two are byte-compared by nothing automatic, and a drift there is invisible until an agent reads one and acts on the other.
- A `<resources>` bullet is not decoration: `component_lint.py`'s `resources-coverage` and `exposes-body-match` checks FAIL an `exposes:` entry with no bullet naming it. Adding an exposure without the bullet ships a grant the occupant has no prose on when to use.
- rbtv goal materialize refuses without taskforce.csv; scaffold-seats --workflow writes it
