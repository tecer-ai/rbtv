The cage half replaces the directional-containment test with `goalsTreeRefusal(goals, target)`: refuse the goals root (or anything containing it), a goal folder's direct root (`rel.length < 2`), anything whose second segment is in `GOALS_WALLED_DIRS` (`seats`, `coordination`), and any leaf in `GOALS_RECORD_FILES` (`sessions.csv`, `state.csv`, `seat.md`, `taskforce.csv`, `goal.md`, `milestones.csv`). ## How it works
A filer's `seat.md` carries `cli-write-roots:` pointing at the engine `register/` (materializer W6). On spawn, `resolveCliWriteRootGrants` feeds each absolute entry through `rwPathRefusal`; `goalsTreeRefusal` returns null for that subfolder, so the cage binds it read-write after the workspace read-root floor. `file-issue file` then writes one markdown into `register/open/<id>.md`. Lifecycle statuses are `open → triaged → approved → building → judged → deployed → verified → closed`; terminal closes are `duplicate`, `invalid`, `wont-fix`. `file-issue doctor` runs `validate_entry` on every open and closed file (missing frontmatter key, class/status off vocabulary, `id` ≠ filename stem, missing `## <id> — ` heading, missing `Destination: ignite-engine`) and refuses `entries-invalid`. `file-issue schema` dumps the keys, classes, and status vocabulary (and, at this commit, the HISTORY entry shape). `file-system-issue/SKILL.md` now points at `schema` instead of restating the class list.

Filing route: `goal-master` and `leader` file through the CLI into the engine register — the "filing wakes nothing" line became "that goal's intake pass sweeps every filing into triage and the owner's digest." `channel-master` routes an ignite/meta defect to those seats and does not file (it previously wrote `build/redesign-plan/loose-ends.md`). `goals-tree/tool/goal_cli.py` tells a caged tool user the same: an ignite/meta defect goes through `file-issue`, never a goal's `issues.md`.
