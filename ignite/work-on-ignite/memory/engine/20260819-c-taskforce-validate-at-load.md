## Design
`8f7b1adf` (2026-08-19 18:37:35Z) puts a validation gate in `readTaskforce` so the four defect classes that used to walk through the door — ragged cell count, duplicate `seat`, a cycle, a dangling `after` — throw a row-precise `Error` instead of being absorbed. Two checks are local and share `readCsv`'s RFC-4180 `splitRow`, so a quoted multi-predecessor `after` is never miscounted as extra columns: `validateTaskforceRows` reports a 1-based file line for cell-count mismatch or a seat named on two lines. The graph half is INVOKED via `goal_cli.py check-acyclic` (`checkAcyclicViaCli`, 60 s timeout) — "the room's ONLY sanctioned acyclicity check" (that verb's own docstring, Rule 9) — never re-implemented. A missing `after` column and a check that fails to run (no python, timeout, junk output) classify as `'no-after-column'` / `{checkFailed}` and are logged once, not thrown. `taskforceFileKey` (mtime+size, no hash) memos both the subprocess and those notices to at most once per file version.

Rejected: a planning-flow redesign (D16); a second JS walk of cycles / dangling `after` / guard-alternate grammar; treating "no `after` column" or "checker unavailable" as refusals (would refuse fixtures that legitimately carry no `after`, and would refuse every load when python cannot answer). The throw needed zero new owner-facing wiring: `lane-watch.js`'s existing `taskforce-unreadable` catch already feeds `err.message` into `alarmOnStall` → `goal-stall-alarm.js`'s catch-all why/head, so a row-precise throw is already a row-precise Slack line.

`79ede919` (18:37:41Z, six seconds later) is the same stall shape inside `queue-request.js#buildUnbuiltSeats`: every registered-but-unbuilt seat's materialize refusal was re-logged at `warn` every ~10 s with no dedup — "N seats × 8,640 identical lines/day" (LE-13, `unbuilt-seats`). Only the log level moves; the refusal, the `failed` array, and `alarmOnStall('unbuilt-seats')` stay. Deliberately its own `unbuiltRefusalMemo`, never `lane-watch.js`'s marker-keyed `failedOn` (sharing it would let one silence the other).

`a64ba6c6` (18:47:57Z) is not extra scope. ## How it works
`readTaskforce` still refuses a missing file and a file with no `seat` rows. After those two historic checks it now calls `validateTaskforce(tfPath)` and only then `readCsv`. On an unchanged mtime+size, `validateTaskforce` re-throws a cached defect or returns without spawning; on a fresh key it runs `validateTaskforceRows`, then (if that is clean) `checkAcyclicViaCli`. Genuine defect → `throw new Error(error)` with strings of the form `<path>:3: row has 5 cell(s), header has 8 — …`, `<path>: seat 'X' is named on lines 2 and 3 — duplicate seat row`, `<path>: after-graph malformed — FINDING [after edge resolves] seat 'alpha' lists predecessor 'ghost'…`, or `FINDING [after graph acyclic] cycle: alpha -> bravo -> alpha`. `no-after-column` / `checkFailed` print once via `console.error` (`readTaskforce` has no logger threaded to it; this still lands in the daemon journal) and load proceeds. Callers that already catch `readTaskforce` — `lane-watch.js` (alarms as `taskforce-unreadable`), `seedGoal` / `uncastSeats`, and `queue-request.js` (still maps a throw to `no-taskforce-yet`, left quiet because the lane-watch branch alarms on the same cadence) — need no new hook.

`buildUnbuiltSeats` buffers per-seat refusals into `toLog`, then computes `sig` = failed seat + code/evidence, sorted so seat order is not a state change. Same `sig` as last pass → every buffered line drops to `debug`; a different set, a different reason, or an empty (all built) set is loud again and the memo re-arms or deletes.
