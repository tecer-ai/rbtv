## Mechanism
Three stacked holes, all in the same `reconcileGoal` target loop. `808902df` (2026-08-19 21:23Z, the original selfheal-to-reconcile build) already had the progress-test primitive: `strike()` compared `prev.signature === signature` and reset the count to 1 on a change. `STRIKE_LIMIT` was 3, per D15. The caller then bypassed that test with `if (launched.ok) clearAttempt(...)`. Class-A owed rows launched the leader every pass and those launches succeeded, so the counter never accumulated — D15 measured launch success, not progress (RCA RC-2). After `2233233a` removed the shortcut and ran `strike()` unconditionally, the `incomplete` signature still carried `:${item.ended}`. `strike()`'s `same` branch therefore never fired twice in a row: each sitting produced a new signature, `same = false`, `attempts = 1`. The primitive was now being consulted, but its input was unstable by construction. After `d813ebcc` dropped the timestamp so the count survived sittings, `strike()` still returned nothing the loop consumed: there was no `attempts >= STRIKE_LIMIT` skip. `seats/resolve-watcher/seat.md:39` had specified report-only in those words ("A successful launch records the attempt; it does not clear it"), so this third hole was faithful to the low-level spec. D34/D40's prose said "bounded, then typed `stuck`"; the spec never gated the launch.

## Fix
Three commits, one policy. `2233233a` (16:21Z, D33a/D34/D35) deleted the `clearAttempt`-on-`launched.ok` shortcut; `strike()` now runs after every launch target (success or failure) and is the only thing that resets the count, driven by whether `signature` changed. `STRIKE_LIMIT` went 3 → 2. End-of-pass `sweepSeats` clears `clearAttempt` for any `(seat, reason)` not in `owedKeys` that pass — the old `if (!derived.owed)` block, generalised. D34 (owner, console): "An attempt is a pass whose owed signature is unchanged, whether or not the launch succeeded; the counter clears only when the owed set changes or empties." All 8 designers had already converged on that shape (RCA table row 6: "D15 conformance, not policy"). `d813ebcc` (17:20Z, D39/D40) drops `:${item.ended}` so the signature is `incomplete:<seat>` and the count survives sittings. Rejected (D40): leaving the spec as written (open-ended relaunch spend; the "2 tries" guarantee is not real); raising the limit above 2 (the bound was already ruled — the defect was that it never fired). Accepted cost: a seat making slow progress that still ends unfinished escalates after 2 attempts; the leader can relaunch it, and escalation is the designed destination. `23de241f` (20:28Z, D44) adds `stuckStands()`: once `stuck` has been emitted for a given `(seat, reason, signature)`, the target loop short-circuits to `{kind:'skip-stuck'}` instead of `launchSitting()`. The brake is keyed on the signature, so a changed owed-set still re-arms launching in the same pass (D34/D40 stay intact). This is a spec change, not a defect-against-spec: D44 supersedes `resolve-watcher/seat.md:39`. Accepted cost: a seat that would have recovered on attempt 3+ gets one fewer chance and comes back through the leader. `d813146d` (2026-08-21) is docs-only — `status.md` recording that D39/D40 landed.

## ATTENTION
- Any code or docs still citing D15's "3 mechanical attempts" are citing a superseded value. The live bound is 2, counted on an unchanged owed signature (D34), never on launch success.
- The signature is the whole load-bearing part: it must stay stable across sittings (D40 dropped `:${item.ended}` for that reason) and must change only when the owed *content* changes (D34). Folding a per-sitting field back into it — the way `ended` was — makes `strike()` see a new item every pass and the bound never fires again.
- D34/D40 only count and emit. `stuckStands` (D44) is what stops the spend, and `affceae2` later keys the enqueue-door brake on the same signature. Changing the count or the signature format here changes when `stuck` fires, when mechanical relaunch stops, and when the door itself refuses. Siblings `20260820-c-verified-done-resolver` and `20260820-c-stuck-becomes-a-brake` share this loop.
- `seats/resolve-watcher/seat.md:39` specified report-only; D44 superseded that line by owner ruling. A later editor who implements the seat spec faithfully will re-open unbounded spend. The live behavior is in `decisions.md` D34/D40/D44, not in that seat.md line.
