## Observed
`meet-transcript-summarizer` sat frozen from 2026-08-23 02:34Z for roughly 13 hours, and the owner alarm that fired into its own Slack channel named the cause as the literal word `undefined`. The posted text read `source-adapter-smith: undefined · meeting-matcher-smith: undefined · cycle-spine-smith: undefined · detection-suite-author: undefined`, alongside a correct and repeated statement that the goal was frozen and "will not clear on its own". The alarm mechanism worked; its message carried zero diagnostic content. Diagnosing the freeze in the end required host journal access that no seat has, which is why it lasted overnight. Separately and invisibly, the refusal CODE recorded for every goal-local lint failure was also wrong: the daemon logged `goal-local-lint-failed`, a generic fallback, and never the real `exposes-ref-dangling`.

## Mechanism
Two defects compounding. First, in `goalLocalLint`'s catch block the evidence was built as `out = String(err.stdout || '') + String(err.stderr || '')` and then parsed as one JSON document via `JSON.parse(out.slice(out.indexOf('{')))`. But `goalLocalArgv` passes `--json`, whose entire purpose is a machine-readable payload on STDOUT, while the tool's prose refusal goes to STDERR. The concatenation is therefore JSON followed by prose and can NEVER parse. Measured on the live tree: stdout is 538 bytes of clean JSON that parses to `refusal.code = exposes-ref-dangling`; stderr is 480 bytes of prose; their concatenation parses as nothing. So the parse always threw, `code` always fell back to `goal-local-lint-failed`, and the refusal's own one-sentence `message` was never recovered at all. Second, the `failed` entries that `buildUnbuiltSeats` returns had NO DECLARED SHAPE: six producers emitted three different shapes — lines 493/500/507 set `code` only, 520 set `error` only, 585/622 set both — and `lane-watch.js` composes the owner alarm from `f.error`. For the three `code`-only producers, including the goal-local lint arm, that renders `undefined`.

## Attempts
This alarm has a documented history of failing and being repaired: `20260820-i-frozen-goal-alarm-fix` (commits 079e08ec, 0c07b144, fc34fb16, f45c3887, 0c39fdfb, 005c3c0c) records it failing three distinct ways within 23 hours of shipping — silent through five freezes, then paging healthy goals, then Slack-looping every 10s. Every one of those repairs addressed WHEN the alarm fires. None addressed WHAT it says, which is the defect here, so the alarm survived all of them still able to name its cause as `undefined`. The register filing on this defect, `G-leader-0823-0217` and the analysis behind build-ignite task 129, blamed only `lane-watch.js` reading `f.error` where the goal-local arm set `f.code`. That was true and it was not the origin: the stdout/stderr concatenation meant the arm had no real code OR message to set in the first place. Fixing only the consumer would have rendered a 400-char raw JSON blob into a Slack alarm and left the wrong refusal code in the journal.

## Fix
Three changes, all at the producer side. `goalLocalLint` now parses `err.stdout` ALONE and returns a `reason` — the refusal's own one-sentence `message` — while keeping the combined stdout+stderr text as `evidence` for the log line, which wants everything. All four goal-local `failed` producers now carry BOTH `code` and `error`, composed from data already present at each site: the milestone list, the sheet path, the lint's reason, the materialize evidence. The two cataloged-lane producers already did. And the entry shape is now DECLARED in a comment at `buildUnbuiltSeats`, because its absence is the actual root cause — with no declared shape, six producers drifted to three shapes and every consumer had to guess. The consumer at `lane-watch.js:456` was deliberately NOT made tolerant: a defensive `f.error || f.code` there would have masked a producer that has not finished diagnosing its own refusal.

## Consequences
Nothing was deleted. `evidence` is retained and still used by the `say('warn', ...)` log line, so the full tool output is not lost — only the alarm's rendering changed, from a raw blob to one sentence. The refusal code recorded in the journal and in `unbuiltRefusalMemo`'s signature is now the real one, which means the memo's "same refusal set" comparison becomes accurate rather than collapsing every distinct goal-local failure into one fallback code — a goal that starts failing for a DIFFERENT reason will now go loud again, which it previously could not. Filed as build-ignite task 129, which should be read together with task 128: the freeze this alarm failed to report was the team-kit resolver regression, entry `20260823-i-goal-local-seats-refused-over`.

## ATTENTION
- Never build a JSON payload by concatenating stdout with stderr. `--json` puts the payload on stdout and the prose refusal on stderr; the concatenation is unparseable, and the failure is SILENT — it degrades to a fallback code that looks like a real one. This hid a wrong refusal code in the journal for as long as the arm existed.
- Do not make `lane-watch.js` tolerant of a missing `error` field. The tolerant read was rejected on purpose: it would mask a producer that has not finished diagnosing its own refusal. Fix the producer.
- Every `failed` entry from `buildUnbuiltSeats` is `{ seat, code, error }` and all three are always set. The shape is declared in a comment there because its ABSENCE is what let six producers drift to three shapes. If you add a producer, set all three.
- An alarm repaired for WHEN it fires is not repaired for WHAT it says. `20260820-i-frozen-goal-alarm-fix` fixed this alarm three times and the message stayed useless through all of them; check the rendered text, not just the trigger.
