## Mechanism
The carve is keyed on the family, not the goal id, so any declaring goal gets it.
`compiler.js#authorizedCarve`'s `CARVEABLE_RO_FAMILIES` set (family-keyed, not goal-keyed) grew a third member, `rbtv-repo`, alongside the pre-existing `vault-wide-read` and `mirror`. Any goal whose plan or seat.md declares an `extraPaths`/`rw-paths` grant that resolves to a path STRICTLY INSIDE `{rbtv-repo}` (never the repo root itself — same-path pairs still conflict, `authorizedCarve`'s first line) now compiles `ok:true` for that narrow subtree while the repo root and every undeclared sibling stay `ro`. The gate is "nothing declares itself": only a plan/seat that explicitly names the path reaches this branch at all.
