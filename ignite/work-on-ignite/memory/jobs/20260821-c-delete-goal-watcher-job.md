## Motivation
d1ca8097 (2026-08-20, `refactor(health): retire the selfheal-room + goal-watcher job machinery (D1/D15)`) stripped every `goal-watcher*` catalogue row and spawn-profile block, deleted the `selfheal-room*` jobs, and then left `jobs/goal-watcher-job.py` on disk: "now dark and unreachable from the daemon — eleven probes guard that program and whole-program retirement was not this scope." The next day's deletion counted twelve dedicated probes; that inventory is the one that shipped. The 3,053-line program had last fired `2026-08-17T11:19:50Z`. Owner 2026-08-21: "if the program is dead, delete it — there must be no dead code." Deadness was measured before the rm, not inferred from the earlier retire: no systemd user unit or timer, no cron, zero `%watcher%` rows in heart.db `jobs` and `queue`, zero journal mentions in 24h, and every remaining mention of the name under `ignite/` a comment rather than a call. D1 (redesign-plan/decisions.md, 2026-08-19) had already named the replacement: the reconciliation loop *is* the per-goal watcher; one watcher per goal owns all health checks; acts first (bounded mechanical retries), escalates second (typed `stuck` to the leader). D15 set the first numbers (3 attempts, 5-minute cadence), later amended by D34. The class this program belonged to is redesign-plan-seed.md §3 theme 4 — watcher/reconcile launching without measuring progress (unbounded relaunch loops, token burn). An earlier, unrelated defect on the same file is `20260815-i-jobcontain-memory-cap-fix` (f79bcdec): the job died silently under jobcontain's 256MB `RLIMIT_AS` for four days; that was patched in place and is not this change.

## Design
9c3aee33 (2026-08-21 13:30:07Z, `chore(ignite): delete the dark goal-watcher-job program and its 12 dedicated probes`) is a pure deletion plus reroute and doc-correction — `git show --stat` is 23 files, +92/−5813 — not a behavior change on any live path. The design alternatives for *how goals are watched* were closed at D1 (reconciliation vs the event/job model this file implemented) and landed as `engine/reconcile.js` in 808902df; this commit does not reopen them. What was rejected here is leaving the dark program as a "maybe we still need it" artifact — that is exactly what d1ca8097 did for one day, and the owner closed it. The twelve probes went with the program because each drove it as its subject: eight `probe-goal-watcher-*`, plus `probe-dead-room-sensor-session`, `probe-headless-retention-unknown`, `probe-watchdog-goal-watcher-arm`, and `probe-lifecycle-exec`. The watchdog and floor-lint edits are catch-up, not a second design: `rbtv-ignite-watchdog` dropped `probe_goal_watcher()`, `RBTV_WATCHDOG_WATCH_JOB`, and the `goal-watcher` row (four rows to three) because the installed unit had already scoped that row off; `floor-lint.py` dropped the `goal-watcher-job.py` allowlist entry and the now-unused `_NS_DEFAULT`. Docs (`ignite/CLAUDE.md`, `jobs/README.md`, `modules/ignite.md`, `team-kit/roles.md`, `attached-execution.md`, `daemon-watchdog.md` and its unit template) were rewritten to name `engine/reconcile.js` as the replacement rather than leave a named hole.

## How it works
There is nothing to run under `ignite/jobs/` for goal-level health. That loop is `engine/reconcile.js`, invoked from `lane-watch.js#maybeReconcile` once per goal tick — filed as `engine/20260819-c-selfheal-to-reconcile.md`, pinned by `engine/probes/probe-reconcile.js`. d1ca8097 already retired the catalogue and profile wiring that could have launched this file; 9c3aee33 removed the leftover program. The daemon-watchdog tool now has three rows (daemon unit, chat-bridge unit, probe-suite timer). Anyone setting `RBTV_WATCHDOG_WATCH_JOB` or looking for `probe_goal_watcher()` is reading a surface that existed only to watch a catalogue row that was already gone; the function's own comment recorded that it measured scheduling, not outcome, and had read `up` through ~200 consecutive `goal-watcher-job` failures (2026-08-11..15). Two neighbors were checked and left live: `lifecycle-exec` is still forked by `coord.py`'s RENEW checkout and covered by `probe-lifecycle-idents.py`; `jobcontain.detach_argv` is still called by `restart-daemon.py` and covered by `probe-detach-env.py`. The team_monitor half of the deleted `probe-headless-retention-unknown` remains inside `team_monitor.py`'s own selftest. `ticker.js`'s per-`exec_id` stall ladder was marked KEEP by d1ca8097 (process silence is not a goal-level owed) and this commit does not touch it.
