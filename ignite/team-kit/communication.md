# communication.md — how a run talks (read once, obey always)

Ships with the kit as-is: a run ADOPTS it by pointing every seat loader at this file.
Amendments inside a live run are that run's leader's rulings, never a seat's edit here.

These rules make saying a thing CHEAPER, never rarer.
**Cheap means low-friction, never low-volume** — measured: less friction, MORE
volunteering.
**[TOOL]** = the tool refuses a breach. **[HAND]** = held by discipline; a breach is silent.

**0 · The volunteer floor — overrides every rule below. [HAND]** No rule here is ever a reason not
to send a fact. Rules govern form, length, address — never WHETHER a finding, correction, premise
failure, or blocker gets said. On any conflict: send the fact, break the rule, name the breach in
one line. A seat that stays quiet to obey this file has broken it.

**1 · Write to 900 characters. [HAND]** The 2,000 cap is a ceiling, not a target. Past ~1,200, stop writing prose and write a file. Length is not
rigour — the file is.

**2 · Claims in the message, evidence in a file. [HAND]** Write the file in your seat folder FIRST; the message carries: one-line outcome · absolute path · what the reader must DO (or `NONE`)
· ≤3 facts to decide whether to open it. Never delete evidence
to fit a message — move it. Bodies with backticks, `$()`, quotes or newlines go
`--file` (**[TOOL]**: substitution guard + cap only; the rest of this rule is [HAND]).

**3 · Five things you do not send. [HAND]** (a) an operational act that succeeded exactly as
requested — `coordinate workers` is the record; (b) an acknowledgement adding no fact — silence
after a clear instruction means you are doing it; declining or diverging IS a fact: send it;
(c) a standing bar already in `conduct.md` / the run's `CLAUDE.md` / `decisions.md` — cite its id;
(d) a second message to the same recipient in one turn — fold it in; (e) praise as its own message — it
rides your next real send. **SEND ANYWAY, ALWAYS:** it failed · it
diverged · a number the requester acts on changed · you noticed something nobody asked.

**4 · Address the seat that must ACT. [HAND]** The leader is a recipient for rulings, lifecycle,
and milestone decisions — not as a witness. Peer work goes to the peer; the leader learns in one clause of your next report.
Carve-outs: an `ask` still goes to the leader; so does any disclosure the leader may override.

**5 · First line states the want. [HAND]** Open `WANT: <one line>. BY: <name>.` or
`FYI — no reply needed.` An `ask` fits one screen: the decision in a sentence · options costed by
one method · a default approvable in ONE word · the event that moots it (or `NONE`). Batch
items; a reply may settle any subset; silence stays HELD — never licence.
Answer with `--type answer --re <ask#>`, always — else the ask stays open.

**6 · Decide inside your scope; send the decision, not the question. [HAND]** Reversible AND on
your own surface → do it, send a `note`: the call, the reasoning, an override invitation.
Only irreversible, cross-surface, owner-gated, or lifecycle calls are asks.

**7 · Correct the smallest thing, once, without narration. [HAND]** Conclusion wrong →
`--supersedes <N>` carrying the corrected fact and nothing else. Wrong fact inside a right message
→ a ≤300-char `note`: message #, wrong string, right value, what stands (`--supersedes` retracts the WHOLE
message). Never narrate being wrong, never thank
in a separate send, never re-send a body to attach a flag.

**8 · One body, one send. [HAND]** Two+ recipients → `create-group` once, send once. `all` only
when a seat that never reads it would act WRONGLY (**[TOOL]**: a `note` to `all` is refused outright,
and any other type to `all` needs `--why`; the judgement itself is [HAND]). A bounded-inbox
seat that missed a broadcast gets the SAME body via `--file`, never a rewrite. A monitoring seat
sends one message per pass, never per flag; answer a batch once, per-item.

**9 · State lives in the state doc. [HAND]** Run state is the run package's state doc (its
`CLAUDE.md` § Run state); your work state is your seat folder. Handovers and renewals carry the
pointer plus ONLY what changed.

**10 · Obey the tool; never `--force`. [HAND]** Types: `completion|ask|answer|verdict|note` — no
sixth. `--why` (`milestone|retraction|roster|ruling`) only on broadcast and required on one;
`--re` required on `answer`, only against an `ask` (**[TOOL]**: every gate in that sentence is
refused at send — but the cap, the guard, the bounded inbox and most of these answer to `--force`,
which is exactly why "never `--force`" is [HAND] and a breach of it is silent; only the type enum
and `--why`-off-broadcast have no escape). Where protocol text and the tool disagree: obey the
TOOL, send direct to leader, disclose in one line.
