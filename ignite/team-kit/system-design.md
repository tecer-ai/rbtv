# team-kit — system design (designer context)

Written by the kit's designer (Claude Fable 5 conductor session "team-builder", 2026-07-24) so a
successor designer inherits the mental model without re-reading the sources. The sources remain
authoritative: `coord.py` (mechanics), `protocol.md` (rules), and the proving runs' evidence
files. Those run packages are named below but are NOT stored beside this kit — `CLAUDE.md` records
the workspace that holds them.

**MAINTENANCE IS MANDATORY (owner-directed).** If you change this system's design — a mechanic in
`coord.py`, a protocol rule, an architecture decision, a known limit closed or opened — update
this file IN THE SAME CHANGE, with the same discipline as the selftest: rationale in, superseded
rationale out (never let a dead WHY stand). A design change this file does not reflect makes the
file a trap for the next designer, which is worse than its absence.

## 1. What this system is, in one paragraph

A file-based coordination layer for N parallel Claude sessions in tmux panes, editing one shared
repo. Three script-managed state files per run (roster, append-only typed message log, groups) +
one CLI (`coord.py`) that wraps every state mutation, plus a rules layer (`protocol.md`) for
everything the tool cannot enforce. A human "owner" sits above; a `leader` agent arbitrates; the
owner starts leader by hand and leader launches everyone else from briefing files.

## 2. The theory the design falls out of

Four properties of agents (from the `kg-edges-visualization-improvements` run package's
`agent-teams-strategic-lessons.md` §1 — the distilled prior-run evidence): **context-bound,
memoryless beyond disk, forkable/parallel, volatile**. Consequences the kit takes as axioms:

- Shared knowledge must be ON DISK, written incrementally (write-through) — chat is not storage.
- Every coordination failure observed was the same defect: **shared mutable state with no owner**
  (prior run D15). So every shared surface gets exactly one writer — the tool enforces it where it
  can (roster rows, cursor column), the protocol where it can't (files, git index).
- **The remedy ladder for a shared mutable surface, strongest first** (S§3.1): **derive-at-read**
  (store no state, so there is nothing to contend) > **isolation** (a worktree or scratch dir per
  writer, so the surface is not shared at all) > **lock** (serialize the critical section) >
  **single-owner by convention** (a rule, subject to §2's D18 — endorsed disciplines don't hold).
  Contention is not carelessness; it is the guaranteed product of writers × surface × time overlap,
  so the rung you pick IS the guarantee you get. Know where the kit stands: the message-id
  allocator and the cursor write are on the LOCK rung (v3 package lock, itself advisory — §5); the
  roster's one-active-row-per-agent is derive-at-read from the log; and every surface that matters
  to the actual work — the repo, the git index, generated projections — is on the WEAKEST rung,
  convention (`R-single-writer`, `R-commit-discipline`, `R-last-lander`). Worktree-per-seat is the
  isolation rung for exactly those surfaces and is designed but unbuilt (§5). When a new contention
  defect appears, climb the ladder before writing another rule — the reflex to reach for rung 4
  first is what left the dominant failure class on convention through three runs.
- **Endorsed disciplines produce zero compliance; only mechanization does** (D18). That is why the
  improvements P1/P2/P12/P15/P22/P26 are CODE, not advice, and why protocol rules exist only where
  code can't reach.
- An append-only log is truthful but goes stale claim-by-claim; an arbiter reading to catch up will
  rule on a withdrawn claim (D13). Hence supersession markers rendered inline, never edits.

## 3. Architecture decisions and their WHY

| Decision | Why (and what it must not regress to) |
|----------|----------------------------------------|
| Kit/package split: kit is run-agnostic code+rules; ALL state lives in the run package via `--package` | Reuse across builds (ledger D-team-kit). The old form (script + state in one run folder) died the day a second run was needed. Never let per-run anything leak into the kit. |
| State files are markdown tables/logs, script-managed, human-readable | The owner watches runs live in an editor; agents debug by reading. The cost (regex parsing, `WORKER_ROW`/`MSG_HEADER`) is accepted. Changing a header grammar breaks reading EXISTING logs — grammar changes must stay backward-compatible or bump a new file. |
| Roster invariant: at most ONE active row per agent; re-check-in supersedes in place (P1) | Ghost ACTIVE rows from dead launches cost the prior run real time and were never resolvable in-run. `checkout` alone can't fix it (the dead pane can't check out). |
| Messages carry a REQUIRED `--type` from the registry's five canonical types (P2) | The tool conforms to the KG's message model (`concepts/message.md`) — the system this kit serves is the one defining it. Types make triage computable (`read --type ask` = leader's drain order). |
| Retraction is a first-class primitive (`--supersedes N`), rendered wherever the old message shows (P12) | D13: a ruling was issued from an already-withdrawn count. The retraction must travel WITH the claim, because readers enter the log at arbitrary offsets. |
| Read cursor is persisted server-side and auto-advances, but ONLY as a default — `--after/--peek/--all` always work (P26; `--after` was named `--last-read` before the 2026-07-25 redesign) | The manual cursor was a defect source; but auto-advance with no override converts a context revert into permanent message loss (prior run §13/§18 proved recovery depends on the override). Both halves are load-bearing. |
| Wakes (keystrokes into panes) are BEST-EFFORT; the log is the only truth; delivery failures are appended into the log (P22) | tmux send-keys silently loses input to busy panes/dialogs (§17). Agents must poll `read` at checkpoints; the failure lines let leader/scientist see the gap. Never build anything that assumes a wake arrived. |
| `wake()` verifies its own Enter actually submitted — captures the pane tail after each Enter and re-sends ONLY Enter (never retypes text), bounded to `WAKE_ENTER_ATTEMPTS` (P35, 2026-07-24, toolsmith-2) | §17.3's text/Enter split (two separate `send-keys` calls) stops the paste-mode combination bug but is NOT sufficient on its own: a pane that is busy/streaming at the instant Enter arrives can still eat the keystroke, stranding the already-typed text in the composer until an unrelated later Enter submits it (live incident, msg #126 — a stale duplicate wake sat unsubmitted in `builder`'s composer mid-turn; scientist hand-fixed it with a bare Enter, never retyping). This REFINES §17.3, does not replace it: text and Enter stay two calls; `wake()` now also polls the pane (`tmux_capture_tail`, on-screen tail with soft-wraps rejoined) and retries the Enter alone when the wake line is still stranded. Falls through to the existing P22 best-effort failure log once `WAKE_ENTER_ATTEMPTS` is exhausted — wakes remain best-effort, this only shrinks the busy-pane window that used to strand delivery. Never widen the retry to retype text: that duplicates the message in the recipient's composer. |
| **Round 2** (2026-07-24, toolsmith-2, verifier-tick #145): round-1's "still the pane's LAST non-blank on-screen line" check is replaced with a STRUCTURAL composer locator, and the unconditional per-attempt sleep is bounded/conditional | verifier-tick's adversarial re-derivation (own scratch tmux panes, real `claude`/`opencode` TUIs) proved round-1's detector was blind on every rostered pane class: claude and opencode both render status/hint chrome BELOW the composer, so the pane's last non-blank line is never the composer — `_wake_unsubmitted` returned "submitted" unconditionally after the FIRST Enter and the retry was structurally unreachable exactly where P35 happened (builder, msg #126). Fix: `_locate_claude_composer` requires the composer be sandwiched between two `─`-rule lines (the top rule may carry the pane's tmux title) — not just a bare `❯` glyph, which a starship-themed shell's PS1 can also emit anywhere in cooked-mode scrollback (verified live: a nested-bash scratch pane's stale PS1 line would false-match a naive "last `❯` line" scan). `_locate_opencode_composer` finds the bottom-most `┃`-bordered box and takes its first non-blank line (the box's LAST non-blank line is the "Build · `<model>`" status footer, not the composer — also verified live). Neither locator is position-from-end: `_locate_composer_line` returns `None` on any pane it cannot classify (codex not covered — no distinguishing structural marker was found safe against false positives in the time budgeted for this fix — and any future/unrostered harness), and callers MUST treat `None` as fail-safe (today's single-Enter behavior: no retry, no reported failure) rather than risk a false stranded-retry or a false delivery-failure on a pane this code cannot read (round-1's cooked-mode `cat` pane got 3 spurious Enters + a spurious failure line under the old heuristic). Latency: the first verify uses `WAKE_ENTER_VERIFY_DELAY_FIRST` (0.15s, down from the old unconditional 0.6s) since the common case does not need to wait for a retry; only an actual retry pays `WAKE_ENTER_VERIFY_DELAY_RETRY` (0.6s) to give a genuinely busy pane time to consume the Enter. Extending composer support to codex (or any future harness) requires the same discipline as this round: capture a REAL live pane in both stranded and submitted states before trusting any structural assumption — round 1 shipped green on a stubbed fixture that hard-coded the exact false assumption it was supposed to catch. |
| **Round 3** (2026-07-24, toolsmith-2, verifier-tick round-2 re-verification #188): wake matching is a bounded PREFIX (`WAKE_PREFIX_LEN`, 60 chars) not the full text, `_locate_claude_composer` accepts a MULTI-line sandwich, and `WAKE_ENTER_VERIFY_DELAY_FIRST` is raised to 1.3s | Round 2's own re-verification found it still inert where P35 lives: every production wake in this kit is 300+ chars (`[coord wake] New coordination message #N from <sender>...`), which hard-wraps in EVERY rostered pane (narrowest 114 cols) — `tmux capture-pane -J` cannot rejoin a TUI's own wrap points, so the full-text match against ONE captured line never matched a wrapped composer (claude: the old single-line-sandwich locator returned `None` on ≥2 composer lines; opencode: its first-box-line locator held only a fragment of the text). Fix: match a bounded PREFIX (unique per send — carries the message number and sender) against the composer's TOP-most line, and generalize the claude locator to accept 1..K lines between the two rules (opencode's locator was already first-line-only, so it needed no change — only the match itself moved to prefix). Verified on REAL captures at REAL wake length (310-323 chars) on both harnesses at the narrowest rostered pane width (114 cols): selftest fixtures are pane tails captured from live scratch `claude`/`opencode` TUIs, not hand-authored strings. Separately, live suppressed-Enter stress (the exact regime verifier-tick #188 demanded, not the "clean sends" evidence rejected twice) surfaced a SECOND, independent defect this same live-stress pass had to close before the fix could be trusted: opencode takes ~0.6-0.85s to redraw a 300+-char paste AT ALL (measured 3x, cold and warm) — during that window the composer is frozen showing its PRE-send content regardless of whether Enter lands, so a check firing before the redraw catches up (round 2's 0.15s) cannot distinguish "genuinely submitted" from "hasn't rendered yet" and silently skips verification on the first attempt, reproducing the P35 symptom by a different path than the wrap bug. Claude Code resolves in <0.15s (unaffected). `WAKE_ENTER_VERIFY_DELAY_FIRST` raised from 0.15s to 1.3s (margin over the observed worst case) closes this — verified live against the real shipped code with the first Enter suppressed on both harnesses: retry fires, the real second Enter lands, and the composer is confirmed empty afterward (not just "wake() returned ok"). Cost accepted: every send now pays the 1.3s first-check delay, not only genuine retries — round 2's "common path is cheap" premise does not hold once the common wake is 300+ chars; correctness was prioritized per the verifier's explicit no-softening standard. A future optimization (distinguish fast- from slow-rendering panes before choosing the delay) is deliberately NOT attempted here — scope was P35 only. |
| Launch reads everything from briefing frontmatter (`agent:` roster signature, `model:`/`effort:`, `observer:`/`auto-wake:`) and GENERATES the boot prompt | Leader must be able to launch with zero briefing knowledge (lazy-read rule) and one command. The briefing file IS the roster entry — no second registry to drift. Observer status is per-run data, so it lives in briefings, not in kit constants (the built-in defaults leader+scientist remain for compatibility). |
| Pane title + delayed `/rename` injection at launch (25s, detached, fail-silent) | Owner-directed naming with zero leader effort. `/rename` is a user-level command reachable only by typing into the session; the delay is a boot-time guess; loss is cosmetic by design — never couple anything functional to it. |
| `selftest` stubs every tmux-touching function (`wake`, `set_pane_title`, `tmux_split_pane`, `tmux_new_window`, `tmux_kill_pane`, `tmux_capture`, `tmux_send_text`/`tmux_send_enter`/`tmux_capture_tail` (P35), `detect_pane`/`live_panes` (identity, 2026-07-25), …) — and every stub's SIGNATURE AND RETURN TYPE must match the real function | The self-test must be runnable on a box with a LIVE tmux (this VPS) without touching real panes. Any new tmux-touching function must go through a module-level wrapper and be stubbed the same way, and every new mechanic gets a check in the same change (kit CLAUDE.md hard rule). The wake stub is switchable mid-test: send-path checks need failing wakes (P22), launch/renew checks need succeeding ones. `wake()`'s own P35 retry logic is exercised for real (not via the wholesale `wake` stub) by stubbing only its three primitives first, before `wake` itself gets stubbed wholesale for the rest of the suite. Round 2's five P35 cases (claude idle/stranded/bounded, opencode stranded, cooked-mode fail-safe) feed the stub REAL captured pane tails (a rostered claude seat's idle composer, scratch claude/opencode/bash panes put into the actual states under test) — round 1's fixture hard-coded the wake line as the pane's last line, the exact false assumption that let it ship blind (verifier-tick #145). |

### v2 decisions (2026-07-24, kg-views-rebuild designer session — owner-interviewed)

| Decision | Why (and what it must not regress to) |
|----------|----------------------------------------|
| Multi-harness launch: `harness:` frontmatter (claude/codex/opencode), per-harness command builders | Owner runs validation seats on non-Claude models (GLM, DeepSeek, Sakana via opencode; Codex 5.6 via codex CLI) under SUBSCRIPTION logins already present on the box. The briefing stays the single source: no harness registry to drift. opencode REQUIRES an explicit `model:` (its own default is not owner-chosen); codex without `model:` deliberately rides the plan default. |
| Worker FOLDERS (`workers/<agent>/agent.md` + loader pair + memory + transcripts), legacy flat form still discovered | The folder is the seat's whole world: briefing, `CLAUDE.md`/`AGENTS.md` loaders (claude AND codex/opencode auto-load their file when cwd = the folder — that is why folder-form default cwd is the folder itself), closer-written `memory.md`, transcript exports. Backward compat is a kit hard rule; dropping flat-form discovery breaks closed packages' replayability. |
| Control-panel layout (owner-ruled, superseding the first hybrid split): the LEADER window holds only the oversight seats — leader, watcher, observers — plus the `panel` overview pane (≤6 panes); every WORKING seat is `window: yes` in its own named tab; closers share ONE dedicated `closers` window (one pane per closer, titled `closer-<target-agent>`), never the leader window (owner-reversed, 2026-07-24, toolsmith-3) | ~20-seat rosters make all-panes illegible and all-windows unglanceable. The owner watches oversight continuously (one glanceable window) and visits working seats by tab. Close/renew maps cleanly onto killing/respawning a window. Closers originally spawned as control-panel panes so closes stayed visible where the owner looked; the owner reversed this — the control panel is for standing oversight seats only, and closer churn (spawned per `close`, killed per `close-seat`) does not belong there. `cmd_close()` now resolves (or creates, on the first close of a run) the shared `closers` window and splits a new pane into it (`resolve_closer_pane` / `closer_placement`, tested headless in `selftest` with no live tmux). |
| `panel` opens an 8-row FULL-WIDTH bottom strip (not tiled) running `tmux-overview --compact` (idempotent via the pane title 'overview'); `tmux_split_pane` re-pins the strip to 8 rows after every tiled relayout; `tmux-overview` renders the plan-usage line from `~/.claude/rbtv-runtime/plan-usage.txt`, which `statusline-usage.py` refreshes on every Claude statusline wake | The first cut tiled the overview equally with the agent panes — a third of the window for 3 lines of signal (owner-corrected on the live run); the second cut collapsed to 2 half-width text lines that dropped seat names and made the usage unreadable (owner-corrected again — "use the horizontal space… maybe even charts"). Compact mode is now a two-block dashboard (`overview-compact.py`): labeled colored usage bars left, windows-with-seat-names right, full pane width, ≤7 lines. Seat names resolve pane→agent from the run roster because claude panes rewrite their own titles — titles are NOT a reliable name source. The post-tile re-pin stops closer spawns from re-inflating the strip. Plan usage (5h/7d `rate_limits`) is only exposed through the statusline payload — pushed, not pullable; persisting it from any live session gives a passively-fresh reading with ZERO credential handling (an owner-rejected alternative was calling usage endpoints with the OAuth token). Model-specific weekly windows render automatically if the payload ever carries them. Worker-provider limits (owner-asked): `provider-usage.py` polls ONLY doc-verified read-only endpoints (Z.AI coding-plan quota-limit — 5h window is unit3/number5, weekly unit6, `percentage` = used; DeepSeek `/user/balance` — money, no windows) and parses codex's LOCAL session `payload.rate_limits` snapshots (fresh only while a codex seat runs — rendered as "as of <time>", never hidden); Sakana exposes no balance endpoint (checked 2026-07-24) and stays labeled console-only. NEVER probe undocumented endpoints with stored keys — a research subagent tried exactly that with the Claude OAuth token and was security-flagged. (Owner ruling 2026-07-24, for the rbtv `teamview` CLI: the single read-only `GET api/oauth/usage` with the stored access token — the exact call Claude Code's `/usage` makes, the only source of model-scoped weekly windows — is SANCTIONED; token refresh/rotation/writes remain forbidden, and the kit's own tooling still makes no OAuth calls at all.) |
| Session memory is a first-class lifecycle: `close <agent> [--renew]` spawns a sonnet closer (kit `closer-prompt.md`) that CO-WRITES `memory.md` with the worker, then `close-seat` kills (+ optionally relaunches) the seat; boot prompt tells persistent seats to read their memory | Context exhaustion was previously terminal — a seat at 90% just degraded. Now a seat is a renewable resource: memory is written WHILE the worker can still correct it (a closer alone summarizes blind; a worker alone at high context summarizes badly). `--renew` closes the loop: fresh session, same briefing, memory carries the state. Ephemeral seats are EXCLUDED by design (fresh-eyes reviewers must not accrete memory). |
| Transcript export = `tmux capture-pane -S -` (uniform across harnesses), `history-limit` raised globally at launch | Only claude exposes machine-readable transcripts; capture-pane works for every harness and is what the closer actually needs (the visible session). The default 2000-line history silently truncates long sessions — raising it at launch is load-bearing for export fidelity. |
| Monitoring is a separate deterministic script (`watch.py`) that IMPORTS coord, not a coord subcommand; context math replicates the rbtv context-monitor hook (last main-chain assistant usage / window) | The watcher loop runs detached for hours — coupling it into coord.py would make every CLI call carry monitor state. Claude-seat transcripts are matched by munged-cwd projects dir + boot-prompt agent name (deterministic, survives parallel sessions); codex/opencode context is NOT externally readable — the honest limit is inactivity-only watching there. Flags re-arm only when the condition clears, so leader gets one ask per episode, not spam. |
| Closer prompt is a KIT template with `{TOKEN}` substitution, spawned as `closer-<target>` | Run-agnostic (kit rule: no per-run content); unique seat name per target lets multiple closers run concurrently; `str.replace` tokens (not `.format`) because the template is markdown full of braces. |
| Transcript discovery falls back to the seat's REGISTERED pane's live `#{pane_current_path}` + a first-user-text `workers/<agent>/` path-fragment match, when the boot-prompt match finds nothing (`find_transcript_by_path_fragment`, toolsmith fix, 2026-07-24) | A hand-started seat (leader — launched by the owner directly, not via `launch`) never carries the standard `"You are agent '<name>'"` boot phrasing, so it silently went unmeasured forever (verified: leader showed no `ctx=` while every launch-started claude seat did). The fallback is keyed only on seat metadata the kit already holds (the roster pane, the agent name) — no run/path/agent special-casing — and requires a path-fragment match (never mtime alone), so a seat with no match on either path stays honestly unmeasured rather than risking a wrong transcript. |
| `window: NAME` in a briefing = SHARED wave window: the first seat of that name creates the window, every later seat splits a pane into it (`seat_placement` pure fn + the generalized `tmux_find_window_pane` lookup; `window: yes` own-window and default-pane behavior unchanged) | Owner-directed (2026-07-24, tv-ux-review run): batch-testing rosters run in WAVES — one window per model wave, one pane per seat — so a 28-seat run stays glanceable as 5 tabs instead of 28. Mirrors the closers-window mechanic (shared window, pane per member) but generalized and briefing-declared rather than hardcoded; selftest covers placement plan + create-then-split. |
| `statusline-usage.py` job 3: persist the session's pid map — `~/.claude/rbtv-runtime/session-pids/<sid>.json` `{pid, transcript, ts}`, pid = the script's claude ANCESTOR (a /proc parent walk; Linux-only, silently absent elsewhere), pruned after 7 days | Every from-the-outside transcript-discovery heuristic (munged-cwd + boot-prompt, path fragments, start-time pairing) mis-claims when sessions share a cwd — observed live 2026-07-24: a pane in the vault root claimed the CONDUCTOR's transcript and showed its context as the pane's. The statusline is the one hook that runs INSIDE every session and is handed `session_id` + `transcript_path`, so it can record the exact pid→transcript pair for free — no credentials, no probing. Consumed by the rbtv `ctx-monitor` CLI (`orchestration/cli/ctx-monitor/`), which feeds `teamview`'s per-pane context/model columns; map entries only appear when a session's statusline next fires (renders go stale through long streaming turns), so consumers keep the heuristic as fallback and additionally EXCLUDE any transcript the map assigns to a live foreign pid. |

### v3 decisions (2026-07-25, `coordinate` CLI UX redesign — owner-ruled T1–T5, mechanics half)

Redesign working doc (findings F1–F18, debate, rulings): the `team-kit-redesign` run package's
`team-kit-redesign.md`.
State-file grammars stayed frozen: `workers.md`/`groups.md` byte-identical, `messages.md` gained
exactly one OPTIONAL header field, and `coordination/.lock` is the only new file.

| Decision | Why (and what it must not regress to) |
|----------|----------------------------------------|
| **Identity is RESOLVED and VERIFIED, never typed** (T1). Order: `--as NAME` > `COORD_AGENT` (injected as a shell-env prefix on every seat's harness command by launch/close/renew) > the calling pane matched against the roster's active rows. A claim contradicting the calling pane's registered agent is REFUSED with the registered name shown (`--force` overrides); unresolvable identity is a teaching error. Every self-naming positional is GONE (`send <to> …`, `read`, `depart`, `checkout`, `create-group`), so positional #1 now ALWAYS means the TARGET seat (argparse dest `target`) and `args.agent` ALWAYS means the caller | F1: identity was hand-typed into every command and never verified — a real sender/recipient reversal recorded leader as the sender of another seat's message (msgs #83/#85), and impersonation-by-typo was silent. Verification is only possible against something the tool OWNS: the roster's pane column. Wakes and the closer template embed the identity-less form, so a seat never re-types its own name. NEVER let a target positional land on `args.agent` again (that collision is what made F14's "positional #1 sometimes SELF, sometimes TARGET" a live impersonation hazard once gates read the caller). `args.agent` remains the internal API for out-of-pane callers (watch.py) — `--as` semantics, and no contradiction can fire outside a pane. |
| **`read` is bounded (`READ_LIMIT`=10) and the cursor advances ONLY through the last message SHOWN, ONLY on an unfiltered non-peek read** (T2 + the designer catch) | F3: a real run logged 305 messages averaging 1,243 chars (48 over 2,000) — an unbounded read floods the reader's context, and reading was the drain every seat performed at every checkpoint. The catch is worse than the flood: a FILTERED read (`--type ask` — leader's own documented drain order) advanced the cursor past every non-matching message, deleting it from that agent's inbox forever with no trace. So `--type`/`--addressed`/`--digest`/`--msg`/`--peek`/`--all` are all peek-semantics and SAY SO in their output, and the batch reports "N more waiting". Never re-couple the advance to the log tail: the tail includes messages the reader was never shown. |
| **Orientation is a command, not a reconstruction: `status`, `pending`, and a `workers` default that shows one CURRENT row per agent** (T2) | F12/F11/F4: recovery after a context loss meant `workers` + `read --peek` + a manual scan, and `workers` printed every historical row with full 560-char summaries. `status` answers "where am I" in one shot (identity, pane liveness, owner, cursor vs log tail, unread by type, asks waiting on me, next command); `pending` derives open asks over the FULL log, never cursor-relative — a cursor-relative view of open work is exactly the reconstruction being replaced. Fix round (2026-07-25): `workers`' lag column and `status`' unread count run the SAME derivation (`unread_for` — addressing- and observer-aware, the agent's own sends excluded), because they were two answers to one question and the coarse one (`log tail − cursor`) reported a seat whose own messages were the tail as behind. Two views of one number must share the derivation, or the run debugs the tool instead of the work. |
| **Ask threading: an optional ` \| re: N` header field, plus derived open-ask state** (T4) | F11: `ask`/`answer` types existed but were UNLINKED, so an unanswered ask was invisible without re-reading the log. An ask is OPEN until an answer/verdict `re:`s it or it is superseded — derived, never a stored status field (a status field is shared mutable state with no owner, the defect class §2 names). The field is ADDITIVE and optional so every pre-T4 log still parses with the same regex; `--type answer` requires it (refusal teaches, `--force` escapes), `verdict` may carry it, every other type is refused — a `re:` on a note would make the derivation lie. |
| **`send` validates its recipient and refuses oversized bodies; bodies may come from a file or stdin** (T3) | F5: a typo'd recipient was accepted silently — the message landed under a name nobody reads and the only signal was one "wake skipped" line. Valid = roster rows ∪ briefing `agent:` names (a seat that exists but has not launched) ∪ groups ∪ `all`, else refused with a difflib closest match. F6: backticks in a double-quoted send body were shell-substituted and corrupted msg #77 — `--file PATH` / `--file -` is a body path that never touches a shell. `MESSAGE_MAX`=2,000 refuses documents-as-messages and teaches the file+3-line-summary fix (every agent pays for a long body at every checkpoint). `--force` escapes all three. |
| **A wake is ATTEMPTED only for a recipient with an ACTIVE roster row AND a pane WHOSE OWN `read` WOULD SHOW THE MESSAGE; every other recipient is SKIPPED — never woken, never logged, named to the sender with its reason (`departed` / `not launched` / `no pane` / `special-case seat` / a closing seat / `not in its inbox` / `bounded inbox: you are not a permitted sender`); and a built-in auto-wake DEFAULT name joins the recipient set only where THIS package knows it (a roster row or a briefing). The attempted wakes are delivered by a bounded thread pool (`WAKE_PARALLEL_MAX`=8), results printed sorted** (T3/T5, generalized in the 2026-07-25 fix round) | F7: wakes to `active=no` seats were logged as delivery failures — 46 noise lines in one run buried the single real failure, which is the whole point of P22's log lines. The first cut fixed only the departed case, so the same defect survived in two other shapes: a briefed-but-never-launched recipient and a never-existing one still produced a logged "failure" for a wake nobody sent, and — worst — `DEFAULT_AUTO_WAKE`'s built-in `scientist` name made EVERY send in a package with no scientist seat log a phantom scientist failure. Unreachability is still reported — to the SENDER, in the summary line, with the reason that distinguishes "this seat is gone" from "this seat never booted" — because the sender must know which recipients got no nudge. F10: `wake()` pays ~1.3s of Enter-verification per recipient (P35 round 3) and they ran serially — a 10-seat broadcast cost the sender ~13s of turn. Never re-derive that pair inline: five hand-written copies of one predicate is what let the drift survive two separate fixes without either being wrong on its own. |

Mechanize it: D18 (§2) says endorsed disciplines produce zero compliance. |
| **One per-package lock (`flock` on `coordination/.lock`) around EVERY read-modify-write; reads stay lockless; an unusable lock degrades to lockless with one note** (T5) | F8: two concurrent sends read the same log tail and claimed the SAME message number (run-obs §589) — ID allocation and append now happen inside one lock hold. The degradation is load-bearing, not laziness: a codex seat's sandbox makes the package read-only, and a coordination CLI that CRASHES where it cannot lock is strictly worse than one that races. Never make the lock mandatory, and never take it around a plain read. |
| **Cursor persistence is NON-FATAL and no-op-guarded; and the cursor belongs to the SEAT, not to one session of it — a check-in inherits the highest cursor any prior row of the SAME agent reached** (T5; inheritance added in the 2026-07-25 fix round) | F9: codex-sandbox seats get EROFS, so their cursor never persists — and the crash cost the reader the batch it had just been shown. Now the messages are shown and an `--after N` hint replaces the traceback. The no-op guard (skip the rewrite when the cursor would not move) removes the pointless write that was itself a race source (scientist-roster #103). Inheritance closes the other half: `checkin` wrote `lastread: 0`, so a re-check-in — and every `close-seat --renew`, which closes the row BEFORE the fresh session checks in — told the seat the ENTIRE log was unread. A renewed seat is the same seat: its memory.md carries the state, and the messages it was already shown are not new. The value is read from the agent's own prior rows only (never another agent's), and the check-in's own "N waiting" count is computed from the inherited cursor, not from #0 — a hint that contradicts the row it just wrote is worse than none. |
| **The runs registry prunes packages whose path no longer exists on load, and NEVER re-points a tag whose package still exists** (T5; no-steal added in the 2026-07-25 fix round) | F15: dead `/tmp` packages accumulated and polluted every `--run` error listing, which is a teaching surface. A tag whose package is GONE is still re-taken — the prune drops it first. Neither selftest (coord's or watch.py's) may write to the real registry: both redirect `RUNS_INDEX` into their temp dir, and watch.py's asserts the real file is byte-identical before and after (it used to leak its temp package into the owner's `~/.config/rbtv/coordinate-runs.json`). |

### v3 decisions (2026-07-25, `coordinate` CLI UX redesign — owner-ruled T6, presentation half)

Same redesign doc and the same frozen surfaces as the mechanics half above: nothing in this block
changes what a command accepts, refuses, writes or computes — only what a reader sees.

| Decision | Why (and what it must not regress to) |
|----------|----------------------------------------|
| **Help is progressive disclosure: the top-level `-h` is a ≤30-line grouped INDEX (everyday / leader / other, one line per command, global flags in a two-line footer), each command's own `-h` carries what/when + argument meanings + ONE worked example + a `next:` line, and the module docstring shrank to a summary that lists no commands at all** | F2/F18: help was inverted. `description=__doc__` dumped a ~120-line manual on anyone typing `-h` (with the subcommand list rendered twice), while `workers -h` and `checkout -h` were effectively empty — the detail sat where nobody needed it and was missing where they did. | **Every command's success output ends with the natural NEXT command, and every refusal states what was refused, why, the fix, and the escape flag if one exists** | The two patterns that already worked in this CLI were the checkin-summary refusal (which teaches the rewrite) and launch/create-group's trailing next command — so they became universal instead of accidental. Hints are derived, never invented: `read` only points at an ask `open_asks` still reports OPEN, `workers` only offers `close-seat` when a row actually shows DEAD?. A hint that fires on a settled ask is worse than none — it spends a turn and teaches the wrong model. |
| **Two output modes, switched EXPLICITLY: plain by default, `--pretty` (or `COORD_PRETTY=1`) for ANSI colour + aligned columns on `status`/`workers`/`read`/`pending` only — never TTY auto-detection** (owner ruling) | The primary reader is an agent, and agents run inside tmux panes: a TTY check — the reflex every CLI reaches for — would hand THEM the human mode by default and put escape bytes into text they re-quote into the log. So the default is byte-plain and the human asks for colour. Colour is applied through one helper (`c(text, code)`) that returns the input unchanged when the mode is off, which is why "plain" is provable in one selftest assertion instead of audited by eye. | **Broadcast wake results compress to ONE summary line (`wakes: N delivered, M failed, K skipped (departed: …)`); only failures keep a line of their own** | A 10-to-20-seat broadcast printed one line per recipient, so the sender scanned twenty lines of chrome for the one that mattered — the same signal-burying that made F7 (46 departed-seat "failures") a defect. Wakes are best-effort by design (P22: the log is the truth), so their per-recipient success is not news; a failure is. Departed seats are NAMED in the summary rather than merely counted — the sender still has to know which seats got no nudge — and both lists are sorted, so the output stays deterministic despite concurrent completion (that determinism was what the parallel-wake selftest asserted before compression; it now asserts the single-line collapse instead). |

## 4. The rules layer (what code cannot enforce)

`protocol.md` holds only rules with measured evidence behind them — a `P`-number (a numbered
proposal from a proving run) or an `S§` pointer (a run-1 strategic finding that was never numbered;
v5 above). Classes: session mechanics (startup round incl. publish-your-contract, cursor,
retraction, checkout), execution discipline (single-writer, grep-then-classify, compute-don't-copy,
bounded waits, commit/index discipline, write-through), decision hygiene (confirm-before-carry,
joint-executability, cost-symmetry, cheap-ask, negative-result, disclose-challenge), and channel
policy. Channel policy is
owner-RULED, not evidence-derived: **only leader initiates owner contact** (R-owner-channel,
2026-07-24) — this consciously reverses the prior run's measured throughput fix (worker
pane-presenting); the compensations are typed-ask triage, escalate-first, batching. If a run shows
arbiter saturation again, the next structural move is a deputy/triage seat — do NOT quietly
re-open per-worker owner channels.

The startup round (protocol item 2) is the newest rule: one intro note per agent in turn order →
groups per overlap → threads live in groups. It exists because the prior run's `all` channel
opened with multicast walls of text and formed its first group at message #16.

## 5. Known limits — the honest list

- **Single arbiter, unbounded queue.** Mitigated (triage, staging, panel absorbing verification),
  not solved. Watch every run for D10-shaped jams.
- **Cross-SESSION collisions are invisible.** coord.py sees one run package; a sibling Claude
  session (or a second run) editing the same repo is outside its model (prior run D28). The
  vault's parallel-session rules are the only guard.
- **The git index is still shared mutable state** (D29). R-commit-discipline is convention;
  worktree-per-worker (P18/P23's durable form) is designed but unbuilt.
- **read-then-advance is not atomic across concurrent readers** of one agent name — the v3 package
  lock serializes the cursor WRITE (and re-reads the roster under it), but the read → decide →
  advance sequence still spans the unlocked read. Acceptable for the same reason as before: one
  agent = one session by construction; do not reuse an agent name for two live panes.
- **The unread filter is keyed on the agent NAME, not on a session or a pane** (v4, Amend.(d)):
  `unread_for` excludes `b["sender"] != agent`, so if two live sessions ever DO share a name, each
  reads the other's messages as its own and skips them — mutually blind, with no marker anywhere.
  v4's `checkin` refusal (§3) closes the way this happened in practice (a zombie double-launch),
  but it is a guard at the door, not a fix to the derivation: `--force`, or two seats hand-started
  under one name, still reach the blind state. Pane-keying the filter would mean recording the
  sender's pane in `messages.md`, i.e. a grammar change to a frozen file that would break replay
  of every closed run — deliberately not done. The invariant stands: one agent name = one live
  session, now enforced at check-in instead of merely assumed.
- **The package lock is advisory and best-effort** (v3). Where `flock` is unavailable or the
  package is read-only (a codex seat's sandbox), coord announces it once on stderr and proceeds
  WITHOUT the lock — i.e. back to the pre-v3 duplicate-ID and lost-roster-write races for that
  caller. This is deliberate (a coordination CLI that dies where it cannot lock is worse than one
  that races), but it means the ID-collision guarantee is "held whenever the lock could be taken",
  never absolute. A run that sees a duplicate message number should look for that stderr note.
- **A cursor that cannot be persisted stays at 0 for the whole session.** The v3 fix makes the
  failure non-fatal (the batch is shown, with an `--after N` hint) — it does NOT give a read-only
  seat a working cursor. Such a seat must carry `--after` itself every read, or re-read messages
  it has already seen; nothing in the tool remembers for it.
- **`workers`' unread-lag column is the EXACT per-agent unread count** (fix round, 2026-07-25):
  it runs `unread_for`, the same derivation `status` and `read` use, so an agent's own sends and
  messages addressed elsewhere no longer inflate it. Cost: the listing evaluates the predicate per
  row (log, groups and briefings are parsed once for the whole listing, not once per agent). It is
  still only as current as each row's persisted cursor — a seat that cannot persist its cursor
  (the read-only-sandbox limit below) reads as permanently behind.
- **Broadcast wakes are bounded at 8 in flight** (v3), so a 30-seat roster still delivers in ~4
  waves of ~1.3s. The bound is deliberate (tmux `send-keys` storms and 30 concurrent captures are
  their own failure mode); raising it needs live evidence, not arithmetic.
- **Pane-based identity is only as current as the roster's pane column.** A seat whose pane
  changed without a re-check-in resolves to no identity (teaching error) — never to a stale name;
  and a seat that never checked in cannot be resolved at all. That is why `checkin` keeps its
  positional name: it is the one command that CREATES the binding.
- **The rename injection can land in a permission dialog** and be lost, or (worst case) as stray
  text in the composer. Cosmetic; accepted; revisit only if Claude Code grows a session-title flag.
- **codex/opencode context usage is unmeasurable from outside** — watch.py monitors those seats
  for liveness/inactivity only. Renew-by-context works only for claude seats; cheap opencode
  seats are ephemeral by design, which sidesteps the gap for the seats most likely to hit it.
- **`wake()`'s P35 Enter-verify does not cover codex panes** (round 2, 2026-07-24) — only claude
  and opencode have a verified, false-positive-safe structural composer locator. A stranded wake
  on a codex pane falls through to the fail-safe path (`_locate_composer_line` returns `None`):
  no retry, no reported failure — the SAME best-effort behavior as before P35, not worse, just
  not improved. Extending coverage requires capturing a real codex pane in both stranded and
  submitted states and finding a marker that cannot collide with codex's own approval-modal `›`
  prompts; not attempted this round (P35's incident and this round's evidence were claude/opencode
  only — see the P35 round-2 row in §3).
- **capture-pane transcripts are lossy** (TUI redraws, scrolled-off dialogs, no tool-call
  structure). Accepted: the closer reads them for substance, and the coordination log — not the
  transcript — remains the decision record. Do not build anything that parses transcripts
  structurally.
- **`close --renew` is two non-atomic steps** (kill, relaunch): a crash between them leaves the
  seat closed but not renewed. The roster shows it (`workers`: row closed, no active row), and
  leader can `launch --only <agent>` by hand — never add hidden retry state to "fix" this.
- **Detached watcher loops survive their seat** (deliberately — nohup) but also survive the RUN:
  killing the run's tmux session does not kill the loop. Close-out includes
  `pkill -f "watch.py --package <this-package>"`; a stale loop from a closed run notifies a dead
  leader roster and is noise, not damage.
- **Approval-gate detection covers only harnesses that publish the state in the pane TITLE**
  (v4, P38) — codex today. A harness that renders its approval modal without changing the title is
  invisible to both the watcher flag and `send`'s blind-gate skip, and falls back to the previous
  behaviour: the seat is woken into the modal, and inactivity finally flags it ~30 minutes later
  with the wrong remedy. Extending coverage means capturing a real pane in the gated state, never
  guessing a marker (P35 round 2's rule). Matching pane TEXT instead is not the escape — it
  false-fires on any seat whose output contains the phrase.
- **Pre-launch validation covers only locally-knowable facts** (v6, PROP-8): alias and slug
  SHAPES, never provider acceptance. A well-formed `provider/model` slug the provider rejects
  (the actual incident slug was shape-valid) still kills its seats at model-init — the
  detection net for that residue is the leftover-window flag (PROP-10) plus deputy's
  checkin-verification sweep, not the pre-flight. Closing it fully would need a provider call
  or a canary spawn, both deliberately rejected (no credentialed probes; a canary spends a
  real seat).
- **System-pressure and leftover-window checks are Linux/tmux-scoped by construction** (v6):
  `system_pressure()` returns None without `/proc`, `window_panes()` returns `{}` without
  tmux, and both read as "unmeasurable — skip", never as healthy or as all-clear. A run on a
  box without /proc simply has no pressure sentinel; nothing substitutes a fake reading.
- **The watcher heartbeat proves the LOOP ran, not that its measurements were right.** A watcher
  whose transcript matching silently resolves nothing still stamps a healthy heartbeat every pass:
  `workers` will say `ok` while context goes unmeasured. Seats that stay permanently without a
  `ctx=` reading in the watcher's own report are the signal for that failure — the heartbeat is
  not.

## 6. Evolution rules (also in CLAUDE.md — repeated because designers land here first)

Selftest green in the same change; evidence pointer for every protocol amendment; no state in the
kit; absolute-path consumers must keep working (repair every run package in the same change if you
move/rename kit files). The provenance chain a designer needs: prior-run `team-observations.md`
(tactical evidence, P1–P26) → `agent-teams-strategic-lessons.md` (theory) → this file (design) →
`coord.py`/`protocol.md` (implementation).
