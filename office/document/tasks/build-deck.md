id: build-deck
description: "Author the presentation deck as agent-written HTML against the picked visual contract and the library Presentation profile, export its PDF, and on a loop-back re-entry patch only the flagged slides."
---

<task-goal>

Turn the frozen narrative and the owner-picked visual direction into one inspectable HTML deck and
its matching PDF, and keep that deck patchable: every verification loop in this workflow re-enters
this act, so the deck must be repairable slide by slide without any part of it being rebuilt.

This act exists because the message and the direction are already settled and nothing downstream may
re-open them. Its whole contribution is faithful execution of a contract someone else agreed.

</task-goal>

<scope>

**Read surfaces.** The goal's shared `planning/` workspace: the blueprint carrying the owner's picked
direction, the gated narrative lock, the visual-communication plan, the art-direction briefs, and the
fill research. On a loop-back re-entry, additionally whichever of the style check, the punch-list, or
the acceptance bounce notes carries the flagged set. The brand pack and the library Presentation
profile, both resolved at run time from the files that own them. The standards library is reached
through its load contract, never read whole.

**Out of scope, deliberately.** The design-extraction tools and the interview transcript are not read
here. The message is not re-opened: neither the narrative lock, the visual-communication plan, nor the
picked direction is amended, blended with a rejected lane, or regenerated by this act. No second
rendering engine is stood up. No slide library, role-token engine, or template-trio stage is used —
this deck is built bespoke.

**The two entry modes.** A first build authors every slide. A loop-back re-entry rewrites ONLY the
slides the incoming list flags and leaves every other slide byte-identical, so the next checker's
diff is exactly the flagged set.

**Escalation, not improvisation.** A required input whose first line is not its marker is a
non-report: the act FAILs to the leader naming the artifact. Roughly three bounces on one slide ends
the polishing and FAILs to the leader with a message-level rethink recommendation. Imagery with no
real provenance HALTs naming the missing asset. Stakes or novelty beyond this pipeline may be refused
outright; bail is a valid outcome.

</scope>

<done-contract>

1. `planning/deck.html` exists, is non-empty, and its FIRST line is the HTML agent-note the standards
   library's production rules require. A file that exists without that first line is a non-report and
   fails this contract — the artifact was created empty at spawn, so presence proves nothing.
2. The deck carries exactly one top-level slide section per slide named in the visual-communication
   plan's slide list — no slide missing, none added.
3. The slide bodies are static markup. No slide body is constructed by script at view time, and no
   charting library is loaded; charts are hand-authored vector or style markup.
4. Every colour, typeface, and size literal in the deck source traces to a brand-pack token or to a
   value the library Presentation profile supplies at run time. No such value is typed from memory.
5. An exported PDF exists beside the deck, produced through the one rendering path, with one page per
   slide and no page clipped.
6. Binary assets, when any exist, sit in the deck's sibling assets folder. No binary is embedded
   inline in the deck source.
7. On a loop-back re-entry: every slide NOT named in the incoming flagged list is byte-identical to
   its state before this re-entry, and every flagged item is either fixed or explicitly recorded as
   unfixable with its reason. A re-entry that changed an unflagged slide fails this contract.
8. On a loop-back re-entry: the narrative lock, the visual-communication plan, the art-direction
   briefs, and the blueprint are unmodified. Any change to those four fails this contract.
9. On a refusal, a halt, or a fail: no partial deck is left presenting itself as finished — the
   product either meets clauses 1 through 6 or the seat's outcome names what stopped it, which
   artifact or asset was missing, and which upstream seat owed it.

</done-contract>
