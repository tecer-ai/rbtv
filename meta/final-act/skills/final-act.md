# Final act

You are closing a session, or doing one of the things a close does. Whatever brought you here, finish the unit of work in progress and wait for your running sub-agents first: a close written over work in flight records a state that is already false. Then do the entry step, then the parts.

## Entry step, on every load

1. **Requests check.** Read the conversation from its start and list every request the user made: each thing asked for, each change ordered, each question asked. For each, write whether it was done and where its result is (a path, or the message that answered it). This is not the loose-ends list: a loose end is work you deferred or found; a request is what the user asked for, and this step exists so that no request is reported done that was not. Show the list as a table. When every request was done, say so in one line. When one was not, or was partly done, ask the user one question with the undone items as its rows and, per row, the choice: finish it now, hand it off, or drop it. Follow the answer before any part below; do not finish an undone request on your own, however small, because the user may have changed their mind about it. When no user can answer (a headless, scheduled or daemon seat), the undone items open the handoff as its first lines, and your final message names them.
2. **Hygiene check.** Every file this session changed that a later agent reads to know what to do next (a task list, a file of decisions, a state, a page an agent follows, code whose interface changed) must show only what is true now. Open each and apply these checks; fix what fails before any part below:
   - A finished task is off the list a later agent treats as open. A checked line on that list is still a line the agent reads: its record goes to the history folder the state names, or to the file the workspace uses for finished work.
   - A decision written in its home has no open question, placeholder or line left that still presents it as open. Two readings of one question are two interpretations.
   - A verb, parameter, command or page removed from what is invoked or followed has no implementing code and no caller left. Commented-out code is still read.
   - The state names, in one place and in this order, what the later agent does first, what is still running and where its result is written, and what waits for whom. The history of how the result was reached is whole, in a folder of its own in the project, and the state names that folder; the state does not contain the history, and the history is not deleted to shorten the state.
   - No old word, field or page sits beside the new one so that nothing breaks before the work is finished: every file a later agent acts on carries the one design. A name the design still uses is not this case; when you cannot tell, ask.
   - A page an agent follows describes the design as it is: no sentence whose only job is to say what the file used to be called or where it was copied from; a comparison with an earlier design goes in the file of decisions, where a superseded decision is replaced, not appended.
   Then read each file as a reader with no memory of the session: what would it do first, what does it think is still running, what would it open the history for? Where an answer is not what you meant, rewrite that place. When a check does not settle the file in front of you, open [State hygiene](../capabilities/methods/state-hygiene.md). A file this session did not change is outside this check.

## Choosing the parts

When the user named a part, do that part. When the user said the session is closing without naming one, propose a set and ask once: loose ends always; triage when the user names a backlog; handoff when work leaves this session unfinished (an item of the requests table not finished, or a task mid-flight); compound when the user corrected you in this session or you noticed a mistake of yours repeat; work history and archivist only when the user asks for them. Run the chosen parts in this order: loose ends (which triages its own list), triage of a named backlog, handoff, compound, archivist, work history. Loose ends comes first because it decides what becomes a task before the handoff writes the state; work history comes last because it collects the session including its close. When no user can answer, run loose ends and handoff and name the parts not run.

| File | CONTAINS | PURPOSE | ALWAYS LOAD WHEN | DO NOT LOAD WHEN |
|---|---|---|---|---|
| [Loose ends](../capabilities/methods/loose-ends.md) | The four classes of loose end, the execute-inline test, and the triage and filing of the rest | Nothing this session deferred, found, left partial or hit as a blocker is lost in chat: each is executed, filed as a task a fresh agent can act on, or disclosed | a job is closing and anything was put off, found out of scope, left partial or hit as a blocker | the job was trivial and nothing was put off |
| [Triage](../capabilities/methods/triage.md) | The value bar (keep, drop, fold, move, owner-decision), the owner round before any write, and the surgical application of the rulings | A backlog holds only entries that earn the owner's attention, ruled by the owner | the user asks to go through, prune, clean up or re-rank a backlog, or complains it is bloated; loose ends also sends its list here before filing | done entries are to be swept out, not judged (archivist) |
| [Handoff](../capabilities/methods/handoff.md) | What a zero-context successor needs, where it is written (the file that tracks the work, or the existing homes brought current), total or partial | A fresh agent continues the work without asking and without redoing anything | work leaves this session for someone else to resume, or the user asks to save where things are | the work is finished and its homes are already current: then handoff answers "nothing to hand off" after checking them |
| [Compound](../capabilities/methods/compound.md) | The collection of the session's corrections and failures, the user's pick of what is documented, and the entry each becomes | Each mistake of the session is one improvement entry, with its cause and the change that would prevent it, in the backlog the user names | the user corrected you in this session, a tool or assumption failed, or you noticed a pattern of your own | the session had no correction and no failure |
| [Archivist](../capabilities/methods/archivist.md) | The sweep of done entries out of task files: delete, or move verbatim to a file the user names | Task files hold only open work | the user asks to sweep, clean or archive done tasks | open entries are to be judged for value (triage), not finished ones swept |
| [Work history](../capabilities/methods/work-history.md) | The collection of a session and its sub-agents: transcripts, recovered outputs, a linked timeline and a manifest, by sub-agents | Someone without the conversation traces what happened, when, by whom and which files prove it | the user asks for the record of a session, plan or project and its agents | the need is a continuation from current knowledge (handoff), not an evidence-backed account |

## Closing message

One message, in this order: the requests table or its one line; the hygiene fixes made; per part run, its own close line (the loose-ends disclosure, the handoff's path or "nothing to hand off" with the homes checked, the compound entries written and where, the archivist's one line, the work-history destination); the parts not run and why.
