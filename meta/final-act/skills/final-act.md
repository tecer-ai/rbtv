# Final act

You are closing a session, or doing one of the things a close does. Whatever brought you here, finish the unit of work in progress and wait for your running sub-agents first: a close written over work in flight records a state that is already false. Then do the entry step, then the parts. For an agent whose conversation never closes (one that answers a thread), the session is the thread the user asks about.

## Entry step, on every load

1. **Requests check.** Read the conversation from its start and list every request the user made: each thing asked for, each change ordered, each question asked. For each, write whether it was done and where its result is (a path, or the message that answered it). This is not the loose-ends list: a loose end is work you deferred or found; a request is what the user asked for, and this step exists so that no request is reported done that was not. Show the list as a table. When every request was done, say so in one line. When one was not, or was partly done, ask the user one question with the undone items as its rows and, per row, the choice: finish it now, hand it off, or drop it. Follow the answer before any part below; do not finish an undone request on your own, however small, because the user may have changed their mind about it. When no user can answer (a headless, scheduled or daemon seat), the undone items open the handoff as its first lines, and your final message names them. When a row of the table claims a status the session did not observe itself ("sent", "paid", "live", "already done"), or the close releases an action that leaves the session (a send, a payment, a filing), verify those rows with the coordinate skill's sanity check before the table is shown as fact; the level is the one its table picks.
2. **Hygiene check.** Every file this session changed that a later agent reads to know what to do next (a task list, a file of decisions, a state, a page an agent follows, code whose interface changed) must show only what is true now. Open each and apply these checks; fix what fails before any part below:
   - A finished task is off the list a later agent treats as open. A checked line on that list is still a line the agent reads: its record goes to the history folder the state names, or to the file the workspace uses for finished work.
   - A decision written in its home has no open question, placeholder or line left that still presents it as open. Two readings of one question are two interpretations.
   - A verb, parameter, command or page removed from what is invoked or followed has no implementing code and no caller left. Commented-out code is still read.
   - The state names, in one place and in this order, what the later agent does first, what is still running and where its result is written, and what waits for whom. The history of how the result was reached is whole, in a folder of its own in the project, and the state names that folder; the state does not contain the history, and the history is not deleted to shorten the state.
   - No old word, field or page sits beside the new one so that nothing breaks before the work is finished: every file a later agent acts on carries the one design. A name the design still uses is not this case; when you cannot tell, ask.
   - A page an agent follows describes the design as it is: no sentence whose only job is to say what the file used to be called or where it was copied from; a comparison with an earlier design goes in the file of decisions, where a superseded decision is replaced, not appended.
   Then read each file as a reader with no memory of the session: what would it do first, what does it think is still running, what would it open the history for? Where an answer is not what you meant, rewrite that place. When a check does not settle the file in front of you, open [State hygiene](../capabilities/methods/state-hygiene.md). A file this session did not change is outside this check.

## Choosing the parts

When the user named a part, do that part. When the user said the session is closing without naming one, propose a set and ask once: loose ends always; compound always, at its default tier, with its full tier proposed when the session was long, ran sub-agents or touched shared surfaces; triage when the user names a backlog; handoff when work leaves this session unfinished (an item of the requests table not finished, or a task mid-flight); work history and archivist only when the user asks for them. Loose ends and compound are two trackers of one kind of find: a loose end is an issue about the matter the session worked on and goes to the project's backlog; a compound entry is an issue about the scaffolding the session worked with and goes to the compound backlog. Run the chosen parts in this order: loose ends (which triages its own list), triage of a named backlog, handoff, compound, archivist, work history. Loose ends comes first because it decides what becomes a task before the handoff writes the state; work history comes last because it collects the session including its close. When no user can answer, run loose ends, handoff and compound (which then writes its entries unruled) and name the parts not run.

## Closing message

One message, in this order: the requests table or its one line; the hygiene fixes made; per part run, its own close line (the loose-ends disclosure, the handoff's path or "nothing to hand off" with the homes checked, the compound entries written per backlog with the candidates routed elsewhere or dropped, the archivist's one line, the work-history destination); the parts not run and why.
