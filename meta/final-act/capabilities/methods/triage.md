# Triage

The result: the open entries of one backlog are ruled by the owner and the rulings applied: keepers kept or moved, dead entries dropped or closed with the reason kept, duplicates folded. You recommend; the owner rules. You never delete, and never file, on your own judgment.

Inputs: the backlog, its scope, the owner's instructions when any (a custom bar, a ranking scheme, "don't delete, only re-rank"; these override the defaults below), and how the backlog is natively written (a tool that owns it, or direct edits). A backlog is a file (a tasks file, a run or goal folder's `issues.md`, a `loose-ends.md`) or, when the loose-ends method sends you here, the list of this session's loose ends not yet filed. Resolved entries are out of scope. Ask only for what the conversation has not made evident. One backlog per run.

You defend the owner's attention: every entry kept or filed is attention spent later, so the burden of proof is on keeping, not on dropping. Truth is not value: a correct observation about a path nobody has hit is below the bar.

## 1. Assess by the value bar

Read each entry's full body, then classify it:

| Verdict | Condition |
|---|---|
| keep | The entry names a cost paid now or on a known date: an observable defect (not one that could fire on an unhit path), an owed teardown (something left running, dirty or armed), content that actively misleads the next agent (a pointer to the wrong place, a stale instruction that already misled someone, not mere staleness), or a dependency of other kept work |
| drop | Latent edge cases nobody has hit, speculative hardening ("could break if"), hygiene whose absence has caused no wrong conclusion, polish, re-verification of what was verified once. When the cost sentence needs "may", "might", "in principle" or "someday", the entry is below the bar |
| fold | A duplicate or sibling of a keeper: merge its context into the keeper, then remove it |
| move | Real value that belongs in another home, because it must outlive this backlog or another owner's list is where it acts: carry its full context there and leave a pointer, not a copy |
| owner-decision | A decision only the owner can make, on which something real waits. A question nobody needs answered is below the bar |

Check staleness cheaply: look for the one fact that would kill the entry (the event it was gated on happened; later work already fixed it). Do not re-investigate the world to rule on an entry.

For a big backlog, or an entry that drags in bulky context, do not read it all yourself: have sub-agents pre-assess in small scopes, as the `coordinate` skill says (its digest capability where present), writing to scratch files, and read their assessments. Every verdict is still yours.

## 2. Owner round

Mandatory before any write. Present in plain words (what is asked, the consequences per option, a recommendation with its reason; every acronym and identifier expanded; multiple choice): the drop list with a one-line reason each (a long list goes to a file reference, not inline chat), each owner-decision as its own question, and the proposed ranking, destinations or filings. Deletion is destructive: never delete without the owner's approval in this session. Where the backlog is an audit record, close entries in place with the reason kept instead of deleting. When no user can answer, write nothing: put the classified list in your final message.

## 3. Apply

Apply the rulings surgically: only the scoped entries, never a reformat, renumbering or an edit to a neighbour. Where a tool owns the backlog's format, that tool is the only writer; never hand-edit around it. Fold an entry's context into the keeper before deleting its source. An entry kept, moved or filed must work cold: a fresh agent acts from its text alone, with what it is, where, why the cost is paid, what was tried, and the state things were left in. A move is done only when the entry works at its destination from its own text alone and the source carries the pointer.

## 4. Close

Report one line each: kept N, moved P (with destinations), dropped M, folded K, rulings applied. The report is the audit trail; write a rationale file only when the owner asks.
