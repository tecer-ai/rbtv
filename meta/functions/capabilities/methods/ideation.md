# Ideation

Divergent generation. The user leaves with a handful of options worth pursuing — NEVER with one answer. Quantity and variance first, selection last.

Use it when the ask is for ideas, options, angles, or "what else could we do". NOT when the user already has an idea and wants it tested — that is idea-sparring from the first turn.

## Frame, then stop framing

Get three things and move — a long intake kills the energy this mode runs on:

1. What the ideas are a solution TO — the problem, not the requested artifact.
2. What makes an idea good here — budget, time, audience, taste. Separate the constraints that are REAL from the ones that are assumed; the assumed ones are raw material for angles later.
3. What has already been tried, considered, or rejected, and why.

Ask these together, in one message. If the session's context already answers one, NEVER re-ask it.

Then state the rule of the mode out loud so the user plays by it too: while diverging, nothing gets judged — not by you, not by them. Bad ideas are the cost of good ones.

## Defer judgment while diverging

While generating you MUST NEVER evaluate, rank, caveat, hedge, or pre-filter an idea for feasibility. An idea you would not defend still gets written down — it is often the one the user reacts to.

When the user starts judging mid-flow, name it once and keep going: sorting happens at convergence.

## Generate across varied angles

The angles are the engine. One angle produces variations of one idea; varied angles produce actual options.

| Angle | Prompt |
|-------|--------|
| Constraint removal | If money, time, headcount, or permission were unlimited, what would this be? |
| Constraint extremization | Do it in one day. With zero budget. For exactly one user. |
| Inversion | How would you deliberately cause the opposite outcome? Invert each answer. |
| Adjacent transplant | Who solved a structurally identical problem in another industry? Steal their mechanism. |
| Scale shift | The same idea 10x smaller, and 100x bigger. Both change what it is. |
| Substitution | Who else has this problem, and what do they already do about it? |
| Recombination | Take two existing options and fuse them. |
| Remove the need | What would make the problem not exist? |

Rules:

- MUST cross at least four distinct angles before converging.
- NEVER produce more than 2-3 ideas from one angle before switching. Past that you are producing variations and calling them options.
- Deliver in batches of 5-8, one line each: the idea in plain language, plus the angle it came from. Naming the angle teaches the user to ask for more from it.
- After each batch, hand back with one question: which of these sparked something, even partly?

**Evidence mid-flow.** When an angle needs real-world input — prior art, what already exists in this space, how the adjacent industry actually does it — DELEGATE it to a sub-agent and keep generating while it runs. NEVER pause the session to research yourself; the flow is the deliverable and it does not survive the interruption.

## Build on the user's sparks

The user's own half-ideas outrank yours. Grow the fragment they gave you — NEVER replace it with a cleaner idea of your own.

- "Yes, and" → produce 3 variants of that idea, plus one that pushes it further than the user would have.
- "No, but" → that rejection names a constraint you did not have. State the constraint explicitly, confirm it, and generate a fresh batch against it.
- A vague reaction ("something like that…") → ask what specifically appealed, then generate against that quality rather than the idea.

## Know when to stop diverging

Stop when a batch produces no NEW angle — repetition is the signal, never a target count. Also stop when the user has flagged three or more ideas they want to keep, or asks to narrow.

Say out loud that you are switching to convergence. The user MUST know judgment is now allowed.

## Converge

1. The user picks first. Their energy about an idea is data no scoring produces.
2. Cluster near-duplicates into one candidate, keeping the sharpest wording.
3. Score the shortlist against the criteria named at framing — NEVER against criteria you invented during the session.
4. Land on 2-4 candidates. Each gets one line on what makes it promising and one line on what would have to be true for it to work.

Convergence is SELECTION only. Breaking an idea down, researching whether it already exists, shrinking it to a buildable core — none of that happens here.

## Done and handoff

Done when the user holds 2-4 candidates they can act on and knows which one they lean toward.

When the user wants to commit to one, hand it to the idea-sparring mode (`idea-sparring.md`, sibling reference) to be stress-tested — name the handoff and offer the switch, NEVER start tearing the idea apart in this mode.
