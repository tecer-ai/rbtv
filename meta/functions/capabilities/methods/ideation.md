# Ideation

The result: the user holds two to four candidate ideas they can act on, and knows which one they lean toward. Ideation never ends on one answer: quantity and variety come first, selection last.

Inputs: the user's ask for ideas, options or angles, and the three framing answers below. Ask for each framing answer the conversation has not already given. When the user already has an idea and wants it tested, this is not the mode: say so and switch to [idea sparring](idea-sparring.md) from the first turn.

## 1. Frame

Get three things, asked together in one message, and then start generating; a long intake costs the momentum that generation depends on:

1. What the ideas are a solution to: the problem, not the requested artifact.
2. What makes an idea good here: budget, time, audience, taste. Separate the constraints that are real from the ones that are assumed; the assumed ones are material for the angles in step 2.
3. What has already been tried, considered or rejected, and why.

Then state the rule of the mode to the user, so that they follow it too: while ideas are being generated, neither of you judges any of them.

## 2. Generate across varied angles

While generating, do not evaluate, rank, caveat, hedge or pre-filter an idea for feasibility. Write down an idea you would not defend: it is often the one the user reacts to. When the user starts judging during generation, say once that sorting happens at convergence, and continue.

One angle produces variations of one idea; varied angles produce distinct options.

| Angle | Prompt |
|---|---|
| Constraint removal | If money, time, headcount or permission were unlimited, what would this be? |
| Constraint extremization | Do it in one day. With zero budget. For exactly one user. |
| Inversion | How would you deliberately cause the opposite outcome? Invert each answer. |
| Adjacent transplant | Who solved a structurally identical problem in another industry? Take their mechanism. |
| Scale shift | The same idea 10x smaller, and 100x bigger. Both change what it is. |
| Substitution | Who else has this problem, and what do they already do about it? |
| Recombination | Take two existing options and fuse them. |
| Remove the need | What would make the problem not exist? |

- Cross at least four distinct angles before converging.
- Produce at most two or three ideas from one angle, then switch angle.
- Deliver in batches of five to eight ideas, one line each: the idea in plain language and the angle it came from. Naming the angle lets the user ask for more from it.
- After each batch, ask one question: which of these sparked something, even partly?

## 3. Build on the user's sparks

The user's own partial ideas take priority over yours. Develop the fragment they gave you; do not replace it with a cleaner idea of your own.

| The user's reaction | Your action |
|---|---|
| "Yes, and" | Produce three variants of that idea, and one that takes it further than the user would have |
| "No, but" | The rejection names a constraint you did not have. State the constraint, confirm it, and generate a fresh batch against it |
| A vague reaction ("something like that…") | Ask what specifically appealed, then generate against that quality, not against the idea |

## 4. Stop generating

Stop when one of these holds: a batch produces no new angle; the user has flagged three or more ideas to keep; the user asks to narrow. Repetition is the signal; there is no target count.

Tell the user that you are switching to convergence and that judging is now allowed.

## 5. Converge

1. The user picks first. Their interest in an idea is information that no scoring produces.
2. Cluster near-duplicates into one candidate, and keep the sharpest wording.
3. Score the shortlist against the criteria named at framing, not against criteria you introduced during the session.
4. Land on two to four candidates. Give each one line on what makes it promising and one line on what would have to be true for it to work.

Convergence is selection only. Do not break an idea down, research whether it already exists, or reduce it to a buildable core here.

## Done when

The user holds two to four candidates they can act on and knows which one they lean toward.

When the user wants to commit to one, name [idea sparring](idea-sparring.md) as the mode that tests it and offer the switch. Do not start testing the idea in this mode.
