# code decisions

Standing decisions about the code component. Each states the decision and its reason; the skill, the pages of `capabilities/methods/` and `capabilities/glossary/`, and the tool pages describe the resulting design.

## One skill for work on code: coding

Building a command-line interface, improving a codebase's architecture, reviewing for over-engineering and the shortcut ledger are method pages under the `coding` skill, not skills of their own. Reason: owner decision, 2026-10-09; they are jobs on one subject, code, done in the stance the skill's body sets, and one entry point with a routing table is the form the meta module's components use.

## The disciplines are the skill's body, not routed pages

The four disciplines (no dead code, no duplicate, no monolith, no patches), the ladder, the shortcut marker, the one runnable check and the closing message are the skill's body. Reason: every change to code needs all of them, so a route to them would be followed on every load; a page read on every load belongs in the body.

## The ladder is the code-level choice; the simplest solution is the design-level one

The ladder (reuse, standard library, native feature, installed dependency, one line, minimum code) decides the form of each piece while writing. The one-sentence simplest solution, the `<simplest>` block of the critical-partner rule where that rule is installed, is written before work starts and is not restated in the skill. Reason: owner decision, 2026-10-09; the two act at different moments, and one instruction has one home.

## Committing is a tool, not a skill

`rbtv-commit` stays, with its page carrying the commit procedure, and the `commit` skill is gone. Reason: owner decision, 2026-10-09; the tool guards a measured collision class on a shared index (a commit meant to carry one file carried four) and was in use, while the skill was mostly the tool's error table, which the tool's page now holds; the framework lists every installed tool for every agent, and keeps committing and reviewing as separate entry points.

## The commit procedure presents the plan and proceeds

The tool's page tells the agent to present the clusters and messages in its message and commit when the user asked for a commit; a push needs the user's word. Reason: a commit the user asked for needs no second question; a push publishes.

## The visual preview of a CLI's screens stays optional

`cli-preview` renders the approved Markdown screens of a CLI design to one offline HTML page; the building-a-CLI method names it as an optional step. Reason: owner decision, 2026-10-09; it is how the owner reviews screens before code exists, and it was used throughout the core CLI build.

## Ponytail is two methods and body text; its plugin parts are not carried

The review and audit skills are one method with a scope (a diff, or the whole tree ranked); the debt skill is the shortcut-ledger method; the main skill's rules are body text of the coding skill. The gain scoreboard, the help card, the intensity levels and the mode mechanics are not carried. Reason: owner decision, 2026-10-09; the scoreboard reports the plugin's benchmarks and the card its commands, which no rbtv agent acts on; a skill opened per task has no mode to persist; the "ultra" level is what the critical-partner counter and frame blocks do.

## The marker is `shortcut:`

A deliberate simplification is marked `shortcut: <ceiling>; <upgrade path>`. Reason: owner decision, 2026-10-09; one plain term per meaning, and the plugin's brand word stays out of codebases. The semicolon separates the two fields because either may contain a comma.

## The architecture report is one HTML file

The improving-architecture method renders its candidates to one HTML file in the OS temp folder and states its path. Reason: owner decision, 2026-10-09; the before/after diagrams are the report's point; on a machine without a browser the file is copied to one.

## The building-a-CLI method keeps its path

`capabilities/methods/building-a-cli.md` and its three sub-pages keep their names and folder. Reason: twenty `capabilities/tools/CLAUDE.md` and `AGENTS.md` files and two core pages link them.
