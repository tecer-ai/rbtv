# `<scope>` — work surfaces

Name the read and write surfaces this task needs, using roles such as “the supplied repository” or “the declared output path” so the task remains portable. The seat request supplies concrete paths.

Separate read from write. A surface with no step that uses it is excess scope; a missing surface forces the occupant to guess. Put command availability in the paired prompt, not here.
