```markdown
# website-relaunch

Relaunch of the company website on a new theme; the brand assets stay in the marketing area.

## Open

| Open | When |
|---|---|
| [_artifacts/board.md](_artifacts/board.md) | ALWAYS first, before any work here. |
| [_artifacts/website-relaunch-tasks.md](_artifacts/website-relaunch-tasks.md) | BEFORE starting, planning or closing any piece of work. |
| [_artifacts/decisions.md](_artifacts/decisions.md) | BEFORE choosing an approach — it may be decided already. |
| [_artifacts/index.md](_artifacts/index.md) | WHEN you need anything else in this folder. |

## Rules

- Site changes go through `theme/src/` and a rebuild — never by editing `theme/dist/`.

## build/

`build/` holds working records: one named subfolder per run or topic, such as `build/theme-audit/`. Nothing goes directly in `build/`: before writing a file there, put it in the existing subfolder of its run or topic, or create one named after it in lowercase kebab-case (dates written with dashes, such as `review-2026-10-01`). A subfolder may nest further by part. When you find a loose file in `build/`, tell the owner; do not move it unasked.

## Tripwires

- BEFORE cancelling the old host: the 14-day fallback decision in the decisions file must have passed.
```
