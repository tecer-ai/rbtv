# Building a unit from a conversation

Use this when the material for a new unit is a conversation that just happened: "turn this into a skill", "save what we did as a command", "make this a rule". It covers what is particular to that case — reading the conversation and interviewing the user — and then hands over to the usual route. It does not replace the unit's own guide.

## 1. Read the conversation first

Before asking anything, find in the conversation:

- the repeatable process, its inputs, and its steps in order;
- what proved each step had worked;
- where the user corrected or steered the agent — these become the unit's rules;
- the tools, agents, and files it used, and what it produced.

## 2. Choose the kind, and where it goes

The user's word ("skill", "command") is a hint, not the choice. Find whether an existing unit already covers the process (`rbtv install list`, `search`, `show`); if one does, change it instead. Otherwise choose the kind of unit and its component, including rbtv or the mirror, with [Choosing what to build](choosing-what-to-build.md), and follow the [entry point and capabilities shape](capability.md) so lessons become capability pages, such as principles, rather than paragraphs in one large unit. Say which kind you chose and why.

## 3. Interview in rounds

Ask only what the conversation did not settle, one round at a time, with named options and a recommendation. Stop as soon as you have enough; a short process needs few questions.

1. The name and the purpose: propose them; the user confirms or renames.
2. The steps, as a numbered list.
3. For each step, where it is not obvious: what it produces that a later step needs; what proves it succeeded; whether the user confirms before it — always before something that cannot be undone, such as deleting, sending, or merging; whether it can run at the same time as another step; and any hard rule.
4. When the unit is used: its triggers, and one similar case that must not use it.

## 4. Write it, show it, then install it

Write the unit as its own guide and its template and schema require; each step states what proves it is done. Show the whole draft and get the user's confirmation before saving. The unit is done when the installer accepts it.
