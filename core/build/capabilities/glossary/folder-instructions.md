# Folder instructions

Instructions for one folder that are meant to reach an agent when it reads or changes files in that folder, and that route the agent to the right file at that moment. The [rbtv installer](rbtv-installer.md) writes a copy for each installed harness; each harness then loads the copies by its own rules, so the moment is met only as far as that harness loads folder files.

Every line is about this folder's own files: it would be false or pointless if the same agent worked in another target folder. A line that would still hold there is a [rule](rule.md): a rule applies to every [task](task.md) of every agent that receives it, whatever folder it works in. A line true only in one subfolder belongs in that subfolder's file. Folder instructions are not an [index file](index-file.md): an index file lists the folder's items. They are not an [exposure method](exposure-method.md). They are a [cognitive unit](cognitive-unit.md) that collects whatever one folder's work needs.

The author writes one file, the basis, chosen when installing (the installer's basis setting, `CLAUDE.md` or `AGENTS.md`). The installer generates the other harness copies from it. Edit the basis file and run the installer again; never edit a generated copy by hand. At the top of the target, the installer keeps a marked section inside the basis file; write author text outside it. Folders the installer does not walk, such as a nested git repository or an excluded path, get no generated copy.

A component can also ship folder instructions, from its `folder-instructions/` source folder. The files there are flat, and each names its target folder, relative to the installation root, in its frontmatter. In the target, the component owns only its marked section inside that folder's folder instructions file: text between markers labeled with its module and component. Two components targeting one folder each own their own section. In an installed [agent](agent.md#installed-agent)'s folder, the installer also writes an agent section that points the agent to its `agent.md` and lists its key folders. Text outside every marked section is the author's and is never touched. The shapes are in the folder-instructions [template](template.md), and the frontmatter's in its [schema](schema.md).
