# Port command

A port command is the command agents call for a [port](port.md), which picks the [connector](connector.md): `message send --to Pia "…"`, `pay pix …`, `calendar list`. The agent names the [operation](operation.md) and its inputs; the port command holds the port's policy, chooses the connector that provides the operation and hands it the work. Swapping a connector is then invisible to agents.

`cast` is the port command of `agent.run`: it launches an agent on any harness, the harnesses are its adapters and the AI labs are its [providers](provider.md). `message` (`connectors/messaging/capabilities/tools/message/`) and `pay` (`connectors/payments/capabilities/tools/pay/`) are the port commands of the messaging and payments ports; `pay` holds the payment gate call, and `asaas pay pix|qr|bill|recharge` still call the gate themselves until the hand-over ends (the R$1 test through `pay`, Sara's tool switched), neither path ever existing without the gate.

## What a port command owns

- **Policy.** `pay` owns the [payment gate](../../../ignite/capabilities/glossary/payment-gate.md) call; `message send` checks the recipient's permission before any connector is called. A connector executes what the port command allowed and holds no policy of its own.
- **The choice of connector.** `message send` names the connector on every send (`--via slack`), so a prompt never breaks when a second connector is installed; `pay` names the account money leaves (`--from asaas`), which is its connector. The installer follows the same rule for a component's `needs`: one provider installs by itself, several ask a person at a terminal or take `--<port> NAME` on the agent path, so no agent path waits on a question ([Agent parity](../principles/agent-parity.md)).
- **The port's operations, as the selected connector provides them.** The port command exposes every operation the port's contract defines; an optional operation the selected connector's record does not list under `provides` is refused with the reason, naming the connector and the operation, never shrunk to what every connector of the port can deliver. A service's own feature that no operation names stays in the connector's command and is used only when an agent's prompt says so.

A port command lives in the port's component under `connectors/`: `connectors/messaging` holds `message`, `connectors/payments` holds `pay`. Core keeps only the harness connection, `cast`. The command is a [Tool](tool.md), built with [Building a command-line interface](../../../../meta/code/capabilities/methods/building-a-cli.md); the connectors it calls are built with [Building a connector](../methods/building-a-connector.md).
