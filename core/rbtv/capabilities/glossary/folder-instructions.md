# Folder instructions

Instructions for one folder that are meant to reach an agent when it reads or changes files in that folder, and that route the agent to the right file at that moment. The [rbtv command](rbtv-command.md) writes a copy for each installed harness; each harness then loads the copies by its own rules, so the moment is met only as far as that harness loads folder files.

Every line is about this folder's own files: it would be false or pointless if the same agent worked in another target folder. A line that would still hold there is a [rule](rule.md): a rule applies to every [task](task.md) of every agent that receives it, whatever folder it works in. A line true only in one subfolder belongs in that subfolder's file. Folder instructions are not an [index file](<../_under-evaluation/guides/folder artifacts/glossary/index-file.md>). They are not an [exposure method](exposure-method.md). They are a [cognitive unit](cognitive-unit.md) that collects whatever one folder's work needs.

The author's text carries an `| Open | When |` table pointing into `_artifacts/`. Each row names a moment, never a bare "see X". Besides the table it holds only one line on what the folder is, the folder's own rules, and one-line tripwires. Facts, state, history, tasks, and full procedures live in artifacts the table points to, not copied into this file. The table lists the folder's `_artifacts/` items. `_artifacts/index.md` lists the folder's other content. No item appears in both. A subfolder's file only adds to its parents. Overriding a parent rule is explicit and states its reason. The file stays under about 150 lines; longer content moves to an artifact the table points to. A rule that must hold at write time lives here, which every harness reads. A folder may add a hook as an extra, never as the only carrier: a hook fires only when the harness was started in that folder. Conventions live here, not in a separate conventions file. A folder that contains `build/` states that nothing sits loose in `build/`: every file goes in a named subfolder, one per run or topic.

The author writes one file, the basis, chosen with `rbtv configure --guidance` (`CLAUDE.md`, `AGENTS.md`, or `none`, which turns copies off). rbtv generates the other harness copies from it. Edit the basis file and run `rbtv update all` again; never edit a generated copy by hand. At the top of the target, rbtv keeps a marked section inside the basis file; write author text outside it. Folders rbtv does not walk, such as a nested git repository or an excluded path, get no generated copy.

A component can also ship folder instructions, from its `folder-instructions/` source folder. The files there are flat, and each names its target folder, relative to the installation root, in its frontmatter. In the target, the component owns only its marked section inside that folder's folder instructions file: text between markers labeled with its module and component. Two components targeting one folder each own their own section. In an [rbtv agent](agent.md#rbtv-agent)'s folder, rbtv also writes an agent section that points the agent to its `agent.md`. Text outside every marked section is the author's and is never touched. The shapes are in the folder-instructions [template](template.md), and the frontmatter's in its [schema](schema.md).
