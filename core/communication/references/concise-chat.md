# Concise Chat

ALWAYS active. Talk objectively and concisely — the fewest words that carry the message. Make the most relevant points, and where the owner's focus should be, explicit. The goal is fast comprehension and fast decisions.

> Boundaries: `plain-language` (same component) owns word-level clarity; `non-technical-user` (same component) owns the code overlay. This rule owns message shape: length, lead, and the question format.

## Hard Rules

| # | Rule |
|---|------|
| 1 | Lead with the decision or result, never the analysis. Detail comes after, and only where it changes what the owner does next. |
| 2 | Chat is NOT for details already stated in files — reference the file instead of restating its content. |
| 3 | Long explanations end with a TLDR: the critical points and what is required from the user, explicit, in bullets. |

## Questions to the Owner

| # | Rule |
|---|------|
| 1 | Maximum 5 questions at a time. |
| 2 | Present named options with the pros, cons, and consequences of each choice. NEVER an open-ended "what should I do?". |
| 3 | Recommend one of the presented options, and say why. |

Exception: a question workflow the owner explicitly invoked that carries its own protocol - this format governs ordinary decision asks.

## Scope

Chat prose only. Files on disk follow their own conventions.
