# Messaging Architecture

A hierarchical communication structure running from a single brand promise down through
audience-specific key messages, evidence, and calls to action. Every piece of communication traces
upward to the promise and downward to concrete proof. Use it when the brand strategy is settled and
copy must now be written for real touchpoints. This reference owns *what the brand says*; how it
sounds is `tone-of-voice.md`.

Without it, ventures write ad hoc copy per touchpoint: the landing page says one thing, the investor
deck another, the onboarding flow a third.

## The sequence

Worked in this order, always. Each step consumes the previous one's output, so a skipped or
reordered step is not a shortcut — it silently invalidates everything downstream of it. The
hierarchy is built top-down, promise first, and every level is finished for all audiences before
the next level starts.

| # | Step | What it produces | What breaks if it is skipped or taken out of order |
|---|---|---|---|
| 1 | Assemble the inputs | The positioning statement, the purpose Why, the identity facets and the validation data, each named as the source a later element will cite | There is nothing to trace to, and the source annotations required at every level below cannot be written |
| 2 | Write the brand promise | One sentence of 15 words or fewer, combining the rational benefit from positioning with the emotional register from the Why, passed through the three filters | Every message below anchors to nothing, and the result is per-touchpoint copy — the exact problem this framework exists to prevent |
| 3 | Name the audiences | The audiences in scope — early adopters, mainstream customers, partners, investors — and what each specifically cares about | One undifferentiated message set gets written, vaguely relevant to everyone and compelling to no one |
| 4 | Write the key messages | 3–5 messages per audience, each supporting the promise, in that audience's own language, each carrying a source annotation | Unattributed messages are opinions; nothing later can tell a validated claim from a hope |
| 5 | Build the proof-point library | 2–3 proof points per message, each with its point, source, type and status — validated or hypothetical | Messages ship as assertions, and the audience learns to discount all of them together |
| 6 | Flag the proof gaps | The messages whose proof is insufficient, flagged for later market validation rather than deleted | A weak message either disappears or passes as proven; neither outcome gets it tested |
| 7 | Map the calls to action | A CTA matrix across awareness, consideration, decision and retention, each CTA naming its channel, its key message and its supporting proof point | Messages with no activation produce a document nobody writing copy will ever open |
| 8 | Run the journey gap analysis | The journey stages that have no message or no CTA, named | The gaps sit in the middle of the funnel where nobody notices them until conversion is measured |
| 9 | Check against the identity facets | An alignment check of every message and proof point against culture, personality and relationship — revising the message, never the prism | The brand says one thing and behaves as another, and the contradiction reaches customers first |
| 10 | Validate the hierarchy | An explicit traceability check: CTAs → messages → promise, and messages → proof | Orphaned messages and unsupported CTAs survive into the brandbook as if they had been derived |
| 11 | Write the audience message cards | One page per audience carrying its messages, top proof points, CTAs and channels | The architecture stays a reference document instead of becoming the tool copywriters actually use |

Nothing here may be worked out of order — in particular, no key message is written before the
promise exists, and no proof point before the message it supports.

## The four levels

### Level 1 — Brand promise

One sentence, maximum 15 words, distilling the positioning statement into a customer-facing
commitment. It combines the rational benefit from positioning with the emotional register from the
purpose Why.

Structure: "[Emotional aspiration] through [rational mechanism]" or "[What changes for you]
because [why we exist]".

Filters: would a real customer nod and say "yes, that is what I want"? Does it connect to a feeling
(confidence, relief, pride, control)? Could a competitor claim it word for word?

### Level 2 — Key messages, 3–5 per audience

Each message must support the promise, address what that audience specifically cares about, use
that audience's own language, and carry a documented source annotation (for example
`[Source: primary customer job]` or `[Source: validated assumption #3]`).

Primary audiences: **early adopters** (feel the pain most acutely, tolerate rough edges) ·
**mainstream customers** (the larger segment after early traction) · **partners** (technology,
distribution, integration) · **investors**.

### Level 3 — Proof points, 2–3 per message

Evidence that makes each message credible, in four types: data points (validation results, survey
percentages, experiment outcomes) · customer language (verbatim interview quotes, never paraphrased)
· feature-as-benefit ("reduces reporting time from 4 hours to 20 minutes") · third-party validation
(analyst citations, press, advisor endorsements).

Each proof point documents: the point itself in one sentence, its source, its type, and its status
(validated or hypothetical).

### Level 4 — Calls to action, by journey stage

| Stage | Customer state | CTA class |
|---|---|---|
| Awareness | Recognizes the problem, has not evaluated solutions | Learn more — blog, demo video, guide, webinar |
| Consideration | Actively comparing options | Try or compare — trial, demo request, case studies, pricing |
| Decision | Ready to commit | Buy or sign up — create account, paid plan, onboarding, contract |
| Retention | Using the product, deciding to expand or refer | Expand or refer — upgrade, invite team, review, referral |

Each CTA specifies the channel it appears in, the key message it connects to, and the proof point
supporting it.

## Traceability

Every element traces to a validated source: key messages to customer jobs, validated assumptions,
and the business model · proof points to validation data, customer quotes, and framework outputs ·
CTAs to the venture's channels and the customer journey stages. **Messages without traceability are
opinions, not strategy.** Where proof is insufficient, flag the message for later market validation
rather than dropping it.

Every message and proof point must also align with the identity facets — culture, personality,
relationship. If a message contradicts the prism, revise the message, not the prism.

## Audience message cards

One page per audience: who they are and what they care about, their 3–5 key messages, the top proof
points for each, and their primary CTAs and channels. These are the operational tool anyone writing
copy actually uses.

## What a good output contains

- Brand promise (≤15 words) with documented rationale.
- 3–5 key messages per audience, each with a source annotation.
- A proof point library, 2–3 per message, each attributed by source, type and status.
- Flagged gaps — messages whose proof is insufficient and needs validation.
- A CTA matrix mapping CTAs to journey stages with channel, message and proof links.
- Journey gap analysis — stages with no message or no CTA.
- Audience message cards for every audience.
- Hierarchy traceability validation: CTAs → messages → promise, and messages → proof.

## Pitfalls

**Writing slogans instead of strategy** — a promise that sounds like billboard copy is too
superficial. **Treating all audiences the same** — one message set is vaguely relevant to everyone
and compelling to no one. **Proof points without sources** — unattributed claims train the audience
to distrust every claim. **Feature-stuffing the message layer** — "we offer real-time
collaboration" is a feature; "your team ships decisions in hours, not weeks" is a message.
**Skipping journey-stage mapping** — messages with no activation produce a document nobody uses.
**Ignoring validation data** — messaging built on assumptions sounds good internally and fails
with real customers.
